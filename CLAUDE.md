# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

Molecular-dynamics study of lipid-membrane pore formation and stability, comparing three force fields — **CHARMM**, **AMBER**, and **SLipids** — across lipids DOPC, DMPC, and DMPG. Pores are driven along a "chain coordinate" collective variable ξ (`pull-coord1-geometry = pore-slices`) that is only available in a custom GROMACS fork (`gromacs-chain-coordinate`), not stock GROMACS. The repo holds the simulation setup machinery, the resulting `.xvg` data, and the Python plotting scripts.

## Pipeline (end to end)

1. **Setup** (`setup_scripts/`, `setup_files/`): build index groups + `.tpr` files for a run.
2. **Simulate on an HPC cluster** via SLURM (`submit_*.sh`) — steered pulling, then umbrella-sampling windows. Produces `*_pullx.xvg` (COM position vs time) and, after `gmx wham`, `*_profile.xvg` (PMF).
3. **Analyze** (`analysis/`): matplotlib scripts read `data/*.xvg` and write PNGs to `plots/`.

Steps 1–2 run on a cluster and cannot be executed here (they hard-code module loads, a `/u/epoppleton/...` GROMACS path, and `sbatch`). Only step 3 runs locally.

## Running the analysis scripts

```bash
python3 analysis/plot_pmf.py            # per-lipid overlaid PMF profiles, each curve min-zeroed
python3 analysis/plot_close_pullx.py    # per-lipid ξ(t) trajectories, one panel per force field
python3 analysis/plot_range_vs_time.py  # per-lipid PMF energy range vs sampling time / start time
```

Each script loops over `LIPIDS = ["DOPC", "DMPC", "DMPG"]` and writes one output
(or output pair) per lipid, suffixed with the lipid name (e.g.
`close_pullx_DOPC.png`, `pmf_profiles_DMPC.png`). The two profile-based scripts
skip lipids that have no `*profile.xvg` data yet (currently only DMPC has PMFs).

Requires only `numpy` + `matplotlib`. Each script derives paths from its own location (`analysis/` → `data/`, `plots/`) via `Path(__file__)`, so run them from anywhere. There are no tests, linter, or build step.

## Equilibrium lipid-property analysis (`lipid_properties.py` + `plot_lipid_properties.py`)

A second, independent analysis branch (not part of the PMF/pulling pipeline) computes bulk membrane properties from the equilibrium MD runs with **lipyphilic**. It is split into a slow compute step and a fast styling step so the analysis need only run once:

```bash
# 1. compute (cluster-side, in the 'lipid64' conda env; slow) -> data/lipprops_*.npz
conda run -n lipid64 python analysis/lipid_properties.py
# 2. plot (anywhere, numpy+matplotlib only) -> plots/lipprop_*.png
python3 analysis/plot_lipid_properties.py
```

- **Input layout**: `~/Simulations/{ff}_{lipid}/eq{1,2,3}/` each holding `memb.gro` + `inbox.xtc`, **both waters-stripped** (override the trajectory name with `--traj`). Override the root with `--sims-root`, or subset with `--forcefields/--lipids/--reps`.
- **Parallelism**: lipyphilic 0.12.1's analyses are all `serial`-only (`get_supported_backends() == ('serial',)`), so MDAnalysis's per-analysis `backend="multiprocessing"` isn't available. Instead the 27 `(ff, lipid, rep)` trajectories are independent single-core jobs farmed across a `multiprocessing` pool with `--nprocs N` (capped at the number of trajectories found; 1 core each). Aggregation is keyed by replicate, so out-of-order completion is fine — parallel output is bit-identical to serial. The script pins BLAS to one thread per worker (`OMP_NUM_THREADS=1` etc., set before numpy import) to avoid oversubscription. Request ≈`--nprocs` cores; e.g. `--nprocs 9` ≈ 3 min, `--nprocs 27` ≈ 1 min for the full set.
- **Topology is `memb.gro`, not `md.tpr`** — both `memb.gro` and `inbox.xtc` have waters stripped (faster universe setup / less to read), so their atom sets match; `memb.gro` is the topology for **both** the MDAnalysis universes and g_lomepro's `-s`. This also sidesteps MDAnalysis's inability to read GROMACS 2026.3's tpx v138 `md.tpr`. (Locally the only equilibrium trajectory present is `charmm_DMPC/eq1`, whose topology can also be stood in by a matching `snapshots/*.gro`.)
- **AMBER `memb.gro` needs residue renumbering first (for the order parameter only)**: GROMACS gives a Lipid17 lipid's two tail residues (`OL`/`MY`) the *same* residue id, and they sit adjacent in the file, so MDAnalysis merges them into one lumpy residue — which breaks the per-tail `reshape` in the S_CC calculation. Renumber `memb.gro` so every tail is a unique residue before running. Only the order parameter is affected: the phosphate-keyed analyses (leaflets/APL/thickness/registration/MSD) stay correct because the heads remain distinct, and CHARMM/SLipids (one properly-numbered residue per lipid) are fine as-is. `scc_profile()` guards this with an up-front carbons-per-residue check that raises an actionable error instead of an opaque reshape failure.
- **Five properties** keyed off one phosphate selection `name P P31` (CHARMM/SLipids name it `P`, AMBER `P31`): leaflets/APL/thickness/registration/MSD via lipyphilic (`AssignLeaflets`, `AreaPerLipid`, `MembThickness`, `Registration`, `MSD`). The order parameter is computed directly in `scc_samples()` (not via lipyphilic's `SCC`) so it can keep the **per-carbon** values: for each C–C bond it takes S_CC = ½⟨3cos²θ−1⟩ with the bilayer normal along z (lipyphilic's default). It stores the *full* per-carbon array — every chain at every frame, pooled over both tails — leaving the averaging to the plotting stage (this is the ~100 MB file; keeping all samples lets the styling stage decide how to reduce it). Tails: CHARMM/SLipids split the two tails by atom name (`C2x` vs `C3x`, N=18 for DOPC else 14); AMBER pools its two `OL`/`MY` tail residues. Carbons within a residue are sorted by acyl number so CHARMM (ascending in the topology) and AMBER (descending) give the same head→tail profile. Averaging over carbons reproduces lipyphilic's per-chain SCC exactly (validated).
- **MSD needs unwrapped coordinates**: lipyphilic's `MSD` assumes no PBC jumps, but the trajectories are wrapped, so a boundary crossing becomes a ~box-length jump that inflates the MSD by ~30–50× (a `dt` red herring — MDAnalysis's `u.trajectory.dt` matches `gmx check` exactly). `analyse()` adds an MDAnalysis `NoJump` transformation *after* the four phosphate/leaflet analyses (which need in-box coordinates for their PBC-aware Voronoi/leaflet logic) and *before* MSD, which is run last. This alone takes DMPC's fitted D from a spurious 5e-7 to a physical ~9e-8 cm²/s.
- **`data/lipprops_{prop}.npz` layout** (one file per property): the three distribution properties (`area_per_lipid`, `memb_thickness`, `registration`) store pooled samples under key `{ff}_{lipid}` plus per-replicate `{ff}_{lipid}_eq{n}`. `memb_thickness`/`registration` are one value per frame (1-D). `area_per_lipid` is **2-D `(n_frames, n_lipids)`** per replicate (frames along axis 0) — the histogram flattens it, but keeping the frame axis lets the trajectory plot show a per-frame mean±SD over lipids; this is the ~60 MB file. `order_parameter` stores `{ff}_{lipid}_carbons` (acyl carbon numbers) + one full per-replicate array `{ff}_{lipid}_eq{n}` of shape `(n_chain_frames, n_carbons)` — the complete per-carbon S_CC for every chain and frame (per-rep only, no pooled duplicate; this is the ~100 MB file, kept full on purpose so the plot can do the averaging). `lateral_diffusion` stores `{ff}_{lipid}_lagtimes`, `_msd` (reps×lag), `_D`, `_Dsem`. (`area_per_lipid` is also ~60 MB — a genuine per-lipid-per-frame distribution.)
- **APL projection maps** — for replicate 1 only, `lipid_properties.py` also renders **upper-leaflet** APL-projected-onto-the-membrane-plane heatmaps to `plots/lipprop_aplproj_{ff}_{lipid}_{avg,final}.png`: `avg` = mean APL over the trajectory, **linearly** interpolated between lipids (a smooth local-APL field); `final` = the last frame, **nearest-neighbour** interpolated so each cell takes its closest lipid's area — i.e. the **Voronoi tessellation** lipyphilic uses to compute APL (discrete per-lipid tiles, on a 1 Å × 1 Å grid). Only one leaflet is shown because APL is defined by a *per-leaflet* Voronoi: tessellating both leaflets' phosphates together gives cells that aren't the APL cells (rasterised cell area correlates with APL at ~0.2 vs ~0.98 for a single leaflet — an opposite-leaflet phosphate nearby in xy clips a lipid's tile, producing the giveaway "small tile, near-maximal APL"). lipyphilic's `AreaPerLipid.project_area()` hard-wires linear interpolation (a single frame comes out smoothly blended, *not* tessellated) and projects both leaflets, so the script drives `lipyphilic.plotting.ProjectionPlot` directly to pick the method and filters to `leaflets == 1`. Lipid positions are the phosphate xy (one per lipid — the same selection APL's Voronoi is built from), so no COM unwrap / bond guessing is needed. Runs *inside* the analysis (needs the trajectory, not just the npz) and *before* the NoJump transform (coords must still be in-box); rendering is headless (`MPLBACKEND=Agg` forced before lipyphilic imports pyplot); any projection failure is downgraded to a warning so it never costs the numerical results.
- **Lipid-trajectory plot** — also rep 1 only, `save_lipid_trajectories()` writes `plots/lipprop_lipidtraj_{ff}_{lipid}.png`: the in-plane (xy) path of every **upper-leaflet** phosphate over the whole trajectory, one per lipid (the `PHOSPHATE` selection), each a distinct colour — a visual for lateral diffusion (MSD) and packing (APL). Paths are **PBC-unwrapped** here (cumulative minimum-image steps) so each is a continuous walk rather than jumping across the box (done explicitly, so it doesn't depend on the NoJump ordering). The ~64 upper-leaflet lipids exceed matplotlib's 10-colour default, so colours come from `palette.evenly_spaced_cmap(n)` — `n` hues evenly spaced around the wheel at *constant HLS lightness* (distinct without a light→dark ramp implying order; `palette.evenly_spaced_colors`/`evenly_spaced_cmap` are the reusable helpers). A dot marks each lipid's final position.
- **Plots** are 1×3 lipid panels (DOPC/DMPC/DMPG) with the three force fields overlaid in the `palette.py` scheme:
  - the three distribution properties → overlaid density histograms (`plots/lipprop_{prop}.png`), each force field's pooled mean marked with a dashed vertical line in its colour. Each also gets a **per-frame trajectory** figure (`plots/lipprop_traj_{prop}.png`) for replicate 1: a 3×3 grid with lipids across columns and force fields down rows, all nine panels sharing the y-axis. `area_per_lipid` (per-lipid) shows the per-frame mean±SD over lipids; the whole-membrane `memb_thickness`/`registration` show their single per-frame value. x-axis is frame index (equilibration is visible here — e.g. AMBER DMPG thickness is still drifting up in rep 1);
  - `order_parameter` → an S_CC-vs-carbon profile drawn the way lipids are shown: carbon number down the y-axis (carbon 1/headgroup at top, tail end at bottom, so the y-axis is inverted and per-lipid — 14 for DMPC/DMPG, 18 for DOPC) with S_CC on the x-axis. The profile is the mean over all chain-frame samples in each replicate; the band is the spread across per-replicate profiles. **Two things about this plot are expected, not bugs** (checked): (1) the profile shows an **even/odd sawtooth** — strongest for the most-ordered tails (SLipids), mild for disordered ones (CHARMM) — because S_CC is a *per-C–C-bond* quantity and consecutive bonds of an ordered, tilted chain sit at alternating angles to the normal (the `C(i-1)→C(i+1)` "director" vector would be smooth but no longer matches lipyphilic's chain average). The NMR-comparable smooth profile is the g_lomepro S_CD one below. (2) The bands are **hairline-thin** because the per-replicate profiles each average thousands of chain-frames, so replicate-to-replicate spread is tiny (~0.001–0.008 vs a signal of ~0.1–0.3);
  - `lateral_diffusion` → a log-log MSD-vs-lag-time curve (mean ± replicate spread) with an inset (linear) bar graph of the fitted diffusion coefficient. The inset auto-places into whichever corner (top-left or bottom-right) the MSD curve overlaps least — computed by projecting the curve into log-log axes-fraction coordinates and counting points inside each candidate rectangle — so it lands above low curves (DMPC/DMPG) and below high ones (DOPC).

  Panels/force fields with no `.npz` data are skipped.

## S_CD order-parameter index files for g_lomepro (`make_order_index.py`)

`lipid_properties.py` computes **S_CC** (C–C bond vs bilayer normal). The more NMR-comparable **S_CD** (deuterium / H–C–H) order parameter is instead computed cluster-side with **g_lomepro** (`-order`), which reads its acyl carbons from a GROMACS `.ndx`. `analysis/make_order_index.py` generates that `.ndx` (numpy + stdlib only):

```bash
python3 analysis/make_order_index.py md.gro                    # auto-detect ff+lipid
python3 analysis/make_order_index.py md.gro -o order.ndx
python3 analysis/make_order_index.py md.gro --ff amber --lipid DOPC
```

- **g_lomepro's index contract** (verified against its source, `order.c`/`g_lomepro.c`, not just the help text): it reads the **sn-1 chain** group then the **sn-2 chain** group, each listing that chain's carbons *per lipid, in chain order*, concatenated lipid-after-lipid (`idorder1[i + j*order_atom_num1]`). S_CD for carbon `i` uses neighbours `i-1`/`i+1` (`for(i=1; i<N-1; i++)`), so the **first and last atom of each chain get no value** — they are neighbours only. The script therefore makes the **carbonyl the first atom** of each chain, so a C1(carbonyl)..C14 chain yields S_CD for **C2..C13** (matches the Gapsys 2013 paper's C2/C7/C13 labels; `reference/gapsys2013computational.pdf`).
- **Double bonds** (`-unsat`): each needs a separate group of **exactly two atoms per lipid** — the two sp² carbons `Ci` then `Ci+1`. DOPC is di-oleoyl (18:1 cis-Δ9) → `-unsat 2` and two double-bond groups (`sn1_double_bond` at C9=C10, then `sn2_double_bond`); DMPC/DMPG are di-myristoyl (14:0) → `-unsat 0`, no double-bond groups. Because all three lipids are symmetric, the sn-1/sn-2 assignment is immaterial.
- **Atom naming** (verified geometrically against `snapshots/`): CHARMM/SLipids use one residue — sn-1 `C21`(carbonyl)..`C2N`, sn-2 `C31`..`C3N` (N=18 DOPC / 14 DMPC/DMPG), DOPC double bond `C29=C210` / `C39=C310`. AMBER Lipid17 splits each lipid into tail–head–tail: the two carbonyls live in the head (`PC`/`PGR`) as `C11` (chain before the head) and `C21` (chain after); tail residues (`OL`/`MY`) name carbons `C1x` = fatty-acid carbon `x` (`C12..C1N`), double bond `C19=C110`. Each tail is paired to its carbonyl by nearest-distance from the tail's `C12`.
- **Robust residue splitting**: raw Lipid17 `md.gro` numbers *every* residue `1`, so sn-2 of one lipid and sn-1 of the next merge into one 100-atom `OL`/`MY` block. The script ignores resid and starts a new residue whenever the resname changes **or an atom name repeats** — validated to split those merged blocks correctly (including lipids that begin mid-block). Index serials are 1-based file positions (= GROMACS serials), so generate the `.ndx` from the same structure whose atom order matches the trajectory — for this pipeline the waters-stripped `memb.gro` ↔ `inbox.xtc`; the renumbered gros used for MDAnalysis's S_CC are **not** needed here.
- The `.ndx` also carries a `Membrane` (all lipid atoms, for g_lomepro's lipid selection) and `Phosphates` (`name P P31`) group. The script prints the detected ff/lipid, lipid count, per-chain atom count, the resulting S_CD carbon range, the `-unsat` value, and the exact group-selection order g_lomepro will prompt for.
- **Running g_lomepro** (built into `lipid_properties.py`): by default the pipeline script runs *both* the lipyphilic npz analysis and, as a second step, the g_lomepro S_CD analysis. `--skip-lomepro` / `--skip-lipyphilic` run just one half; the g_lomepro half needs only numpy + the binary (the MDAnalysis/lipyphilic imports are optional, guarded behind `_HAVE_LIPYPHILIC`), so it can run on a bare node with `--skip-lipyphilic`. For each `{ff}_{lipid}` it (re)builds the shared `{ff}_{lipid}/lomepro.ndx` via `make_order_index.generate()` from a replicate's `memb.gro` (imported, not re-shelled; serials must match the waters-stripped `inbox.xtc`), then for every replicate makes a fresh `eq{rep}/lomepro/` (overwriting any previous one) and runs, from the `eq{rep}` dir, `echo "<groups>" | g_lomepro_static -f inbox.xtc -n ../lomepro.ndx -s memb.gro -lip_num <N> [-unsat 2] -order lomepro/scd.out`. `-lip_num` = lipid count (auto-detected, =128 here); the `sn{1,2}_double_bond` groups and `-unsat 2` are added only for DOPC (myristoyl DMPC/DMPG select just `Membrane sn1 sn2`). It then copies `lomepro/scd.out_AVG_sn{1,2}.dat` → `data/{ff}_{lipid}_{rep}_scd_sn{1,2}.dat` (one file per replicate, kept as separate samples). Binary path defaults to `~/software/g_lomepro/g_lomepro_static` (`--lomepro-bin` to override). g_lomepro (a GROMACS tool) needs `GMXLIB` pointing at GROMACS's data dir; the script sets it in the subprocess env — respecting an existing `GMXLIB`, else deriving it from `gmx` on `PATH` (`<prefix>/bin/gmx` → `<prefix>/share/gromacs/top`).
- **Plotting** (`plot_scd()` in `plot_lipid_properties.py`): reads g_lomepro's `_AVG_sn{1,2}.dat` output, in `data/` as `{ff}_{lipid}_{rep}_scd_sn{1,2}.dat` (columns `carbon_number, mean(-S_CD), sd` — the two data columns are the g_order-style mean and its standard deviation over lipids×frames, **not** the two tails). Drawn like the S_CC profile (`plot_order_parameter`): carbon number down an inverted per-lipid y-axis, `-S_CD` on x, force fields overlaid, → `plots/lipprop_scd.png`. The two tails are averaged *within* each replicate (justified because for these symmetric di-oleoyl/di-myristoyl lipids the sn-1/sn-2 profiles differ by <0.01, the only non-trivial gap being ~0.03 at the C9=C10 double bond), then the line is the mean over replicates and the band the SD across them — see the error-bar convention below.

- **Error-bar convention (consistent across all point-estimate plots)**: bands/error bars are **± SD across the per-replicate means** — S_CC, S_CD, the MSD curve, and the fitted-D bars all reduce each replicate to one summary (a profile, curve, or scalar) and take the population SD over the (typically 3) replicates. This is deliberate: MD frames are autocorrelated, so a CI over all pooled frames would be pseudoreplication (hairline, understating uncertainty); the replicate spread is the honest reproducibility measure. The distribution plots (`area_per_lipid`/`memb_thickness`/`registration` histograms) are the exception by design — they show the full pooled-across-reps *distribution*, not a mean ± error.

## Density-profile index files for gmx density (`make_density_index.py`)

`analysis/make_density_index.py` builds a GROMACS `.ndx` per force field / lipid for `gmx density`, from the **full (water + ion)** `.gro` files in `tmp/` (these are the whole system, *not* the waters-stripped `memb.gro` used for lipyphilic). Writes `data/density_{ff}_{lipid}.ndx` with a **constant 8-group layout** (so a density loop needs no per-lipid conditionals): `water`, `sodium`, `magnesium`, `calcium`, `phosphorus`, `glycerol_C2`, `midpoint_C`, `terminal_C`. Only the underlying carbon varies by lipid — `midpoint_C` = the upper C=C carbon C9 for DOPC, mid-chain C7 for DMPC/DMPG; `terminal_C` = the last acyl carbon (C18 for DOPC, C14 for DMPx). Both cover both chains.

```bash
conda run -n lipid64 python analysis/make_density_index.py           # all tmp/*.gro
python analysis/make_density_index.py tmp/charmm_DOPC_md.gro         # a subset
```

- **Selections** are built from resname/atom-name masks and written with `MDAnalysis.selections.gromacs.SelectionWriter` (masks, not selection strings, so AMBER's `Na+`/`Cl-` don't trip the parser). Water/ion resnames are auto-detected (`water` = TIP3/TP3/SOL; `sodium` = SOD/Na+/NA; `calcium` = CAL/CA; `magnesium` = MG), which also pins the force field (TIP3→CHARMM, SOL→SLipids, TP3/OL/MY→AMBER).
- **Acyl-carbon naming**: CHARMM/SLipids keep both tails in one residue so a chain position matches `C2{n}`+`C3{n}` (128+128); AMBER's two tail residues (`OL`/`MY`) both use `C1{n}`, so one position matches 256. Glycerol `C2` and phosphate (`P`/`P31`) live in the single residue (CHARMM/SLipids) or the head residue `PC`/`PGR` (AMBER). DMPG carries 128 Na⁺ counterions (`sodium` ≈ 141) vs ≈14 for the neutral PC lipids.
- Empty groups (an ion species absent from a system) are skipped with a warning, since `gmx density` errors on an empty group. Indices are 1-based GROMACS serials from the full-system gro, so run `gmx density` against the matching full-system trajectory (not `inbox.xtc`). Output lands in the gitignored `data/`.
- **Plotting** (`plot_density.py`, numpy+matplotlib): reads `data/{ff}_{lipid}_density.xvg` (gmx density output; columns mapped to group names via the `@ sN legend` header) and draws a 3×3 grid (lipids across columns, force fields down rows) → `plots/density_profiles.png`. Each curve is **peak-normalised** (÷ its own max, so abundant water doesn't dwarf the sparse ions) and each panel's z-axis is **shifted so the `terminal_C` peak is at 0** (the bilayer centre). Colours: water blue, Na⁺ purple, Mg²⁺ green, Ca²⁺ teal, P orange, and the three carbons in greys from black (`glycerol_C2`, head) through mid-grey (`midpoint_C`) to light-grey (`terminal_C`, tail). Mg²⁺/Ca²⁺ (1–4 atoms) are computed in the index but **dropped from the plot** (`GROUPS`) — peak-normalising 1–4 atoms just amplifies noise into the already-busy head-group region.

## Pore radial-density maps for the out-of-equilibrium runs (`pore_density.py` + `plot_pore_density.py`)

A third, independent branch: for the **pore** simulations (a pore driven open by external forces, then a chain-coordinate *rerun*), it builds cylindrically-averaged **(radius, z) density maps** of selected atoms around the pore centre. Same compute→npz→plot split as the other branches.

```bash
# 1. compute (cluster-side, MDAnalysis env) -> data/poredens_{ff}_{lipid}.npz (+ poredens_counts_{ff}_{lipid}.npz)
conda run -n lipid64 python analysis/pore_density.py            # discover all 9
conda run -n lipid64 python analysis/pore_density.py tmp/       # one explicit dir
# 2. plot (anywhere, numpy+matplotlib only) -> plots/poredens_{water,phosphorus,glycerol_c2,midpoint_c}.png
python3 analysis/plot_pore_density.py
python3 analysis/plot_pore_counts.py                            # -> plots/poredens_counts.png
```

- **Discovery mirrors `lipid_properties.py`**: with no positional args it iterates `--forcefields × --lipids` under `--sims-root` (default `~/Simulations`) and looks in `{ff}_{lipid}/{--run-subdir}/` — default `umbrella23` (the pore run is umbrella window 23, one per system, **no replicates**, hence "all 9"). Positional run dirs override discovery (each must hold the `md.{xtc,gro}` + `rerunerr.log` triple), which is how the local `tmp/` test set (from **amber_DMPC**) is run — so only that panel fills in locally; the other 8 render blank. Missing dirs are skipped with a per-system message.
- **Input per run dir**: `md.xtc` + `md.gro` (the **full** water+ion system, *not* the waters-stripped `memb.gro`) and `rerunerr.log`, the chain-coordinate rerun log. The pore centre for each frame is parsed from lines `Cylinder center at (X/Y/Z):  cx cy cz` (nm) via a regex; there is one such line per frame (here 1001 centres ↔ 1001 frames, zipped in file order — the centre barely moves, ~0.2 nm, so any off-by-one is negligible).
- **Four selections**, reusing `make_density_index.detect` + `build_groups` so the per-ff/-lipid water & lipid atom names are handled automatically (the user's reminder — water/lipid names differ per simulation): `water` (reduced to **oxygens** — names `O`/`OW`/`OH2`), `phosphorus`, `glycerol_C2`, `midpoint_C` (mid-chain C, DOPC C9 / DMPx C7, both tails). `terminal_C` etc. from the index are unused here.
- **Binning**: per frame, each atom's in-plane distance `r` from that frame's pore centre (**minimum-image in x/y**) and its **absolute** z go into a 2-D `(z, r)` histogram (fixed edges shared by every run: `r` 0–3 nm, `z` 0–9 nm, both Δ=0.05 nm, so all maps are directly comparable). MDAnalysis positions are Å; centres (nm) are ×10 to match, distances /10 back to nm.
- **Shell-volume normalisation is the point**: raw counts grow with `r` (more area), which would wrongly brighten bulk regions at large r. Counts are divided by the annular shell volume `2π·r·Δr·Δz` (as `π(r_out²−r_in²)·Δz`) and the frame count → a number density in atoms/nm³, so uniformly-filled regions read **flat** across r and the pore feature is what stands out.
- **Colour normalisation is shared across all nine panels** (one scale per atom-type figure, *not* per-panel) — deliberately, so the water-in-pore density can be **compared between force fields** (read down a column: same lipid, the three ff). The shared peak is a **high percentile** (`PEAK_PCTL = 99.5`) of the pooled bins, not the raw max: the innermost radial shells (r→0) have tiny volumes, so dividing counts by them produces a few noise spikes (~2× bulk) that would otherwise grab the whole top of the colour scale and mute the pore contrast. For water the percentile peak ≈ the bulk-water density, so bulk reads ~0.75–0.85 and the pore depletion fills the lower range. The zoom figures use the same shared-percentile scheme but computed **within the CV region** (a separate scale). Small bright specks at r≈0 are the residual tiny-shell noise clipped to 1.0 — expected, not signal.
- **Reading the maps** (validated on amber_DMPC): *water* shows two flat bulk slabs (top/bottom) with a depleted membrane core at large r that **recedes at small r** — water intruding along the pore axis. *phosphorus* shows the two leaflet head-group bands curving **inward** toward the mid-plane at small r — the lipid-lined **toroidal pore** rim. The small-r speckle (r ≲ 0.2 nm) is expected low-count variance in tiny shells, not a bug.
- **Plotting**: `plot_selection(key, stem, title, region=None)` draws a 3×3 grid (lipids across columns, force fields down rows) with `imshow` (viridis, origin lower, `extent` from the edges), radius on x and z-relative-to-pore on y, shared axes, one shared colourbar. Missing `.npz`/selection → blank panel. `aspect="equal"` (1 nm is the same size on both axes, so panels are tall strips, *not* square — intentional; enforced via `set_aspect("equal", adjustable="box")` on **all** axes after setting identical limits, since with `sharex/sharey` only setting it on data panels lets the box get squeezed and 1 nm then differs between x and y). Two figure sets are written:
  - **Full maps** (r 0–3, z ±4.5 nm), all four selections → `poredens_{water,phosphorus,glycerol_c2,midpoint_c}.png`, peak-normalised over the whole map, with a thin dotted **cyan rectangle** outlining the CV cylinder (`CYL_R=0.9`, `CYL_H=2.7` nm → r∈[0,0.9], z∈[−1.35,1.35]).
  - **Zoom maps** restricted to the CV cylinder (`region=(CYL_R, CYL_H/2)`), **water + phosphate only** → `poredens_zoom_{water,phosphorus}.png`, peak-normalised **within the region** (so the zoomed content uses the full colour range) and no rectangle (it *is* the frame).
  Narrow panels drop the edge x-tick under the auto-locator, so ticks are set explicitly (integers 0…3 for the full map; 4 evenly-spaced 0…`r_hi` for the zoom).
- **Per-frame in-cylinder occupancy** — alongside the density maps, `pore_density.py` also writes `data/poredens_counts_{ff}_{lipid}.npz`: the **raw per-frame count** of atoms inside the chain-coordinate CV cylinder for the three `COUNT_SELECTIONS` (`water` oxygens, `phosphorus`, `glycerol_C2`). Counted over **two z-slabs**: the **full** cylinder (`CYL_R=0.9`, `CYL_H=2.7` nm → r≤0.9, |z|≤1.35 relative to that frame's pore centre) and its **middle third** (|z|≤`CYL_H/6`=0.45 nm, the central 9 Å — the pore's narrowest waist). Keys: `frame`, `time_ps` (from the trajectory timestamps), `cyl_r_nm`/`cyl_h_nm`/`cyl_mid_h_nm`, one 1-D count array per selection for the full cylinder, and a `{name}_mid` array for the middle third. Computed inside the same frame loop as the histograms (both masks reuse the per-frame `r`/`z` already needed for binning). `plot_pore_counts.py` (numpy+matplotlib, `palette`) plots these as occupancy-vs-time trajectories in a **3×3 grid with atom type down the rows** (water/phosphate/glycerol C2) and **lipid across the columns** (DOPC/DMPC/DMPG); within each panel the three force fields overlay as lines in the `palette` colours (CHARMM blue / AMBER green / SLipids gold), each row sharing a y-scale. Two figures: `plots/poredens_counts.png` (full cylinder) and `plots/poredens_counts_middle.png` (middle third, from the `_mid` keys).

## Lipid tilt modulus with OpenStructure / ost_pymodules (`tilt_convert.py` + `tilt_modulus.py` + `run_tilt.sh` + `plot_tilt_modulus.py`)

A fourth equilibrium-analysis branch: the membrane **lipid tilt modulus** χ per force field / lipid, using the Harries-group `ost_pymodules` code (`~/software/ost_pymodules/lipid_analysis.py`; Khelashvili et al. 2013 JCTC 9:3866, `reference/khelashvili2013calculating*.pdf`). Inputs are the equilibrium runs downloaded to `traj/` as `{ff}_{lipid}.gro` (+ `.tpr`) topology and three replicate `{ff}_{lipid}{1,2,3}.xtc` (9 systems × 3 reps = 27 trajectories, all water-containing).

**Why two stages / two conda envs.** OpenStructure only reads PDB/CRD + **CHARMM DCD**, runs under **Python 2.7**, and has no MDAnalysis. So stage 1 (`tilt_convert.py`, run in `lipid64`) reads `gro`+`xtc` and writes `data/tilt_{ff}_{lipid}_{rep}.{pdb,dcd}`; stage 2 (`tilt_modulus.py`, run with the **OpenStructure python**, `~/miniconda3/envs/openstructure/bin/python`) does the analysis. A full-trajectory multi-model PDB is *not* used — OST loads it only as a list of every frame's entity (memory-punishing); the compact DCD streams frame-by-frame.

**OST build specifics (this machine).** The `ost` here was compiled **with** the image (IPLT) libraries — required, since the membrane normal comes from a water/lipid **density** interface (`img.CreateImage`, `EntityToDensityRosetta`); without img the method cannot run. Two things a plain python (vs the interactive `ost` launcher) must set up, both handled in `tilt_modulus.py`: (1) `import ost.img` so `ost_pymodules`' `from ost import *` resolves `img.*`; (2) `SetPrefixPath` to OST's install root (`$DNG_ROOT`/`$OST_ROOT`, else walk up from `ost.__file__` to the dir holding `share/openstructure`) so `EntityToDensityRosetta` finds `atom_scattering_properties.txt` (else "missing PrefixPath").

**`tilt_convert.py` preprocessing** (all force-field-specific fixups so `AnalyzeLipidTiltAndSplay` sees each lipid as ONE residue with a head→tail vector inside it):
- **Heavy atoms only** (drop `name H*`) for lipids *and* water, applied to all three force fields for a consistent density and because it removes the AMBER hydrogen-name collisions below. The interface density and the tilt director are heavy-atom quantities, so this is a negligible, deliberate deviation from the all-atom paper.
- **AMBER residue merge.** Lipid17 splits each lipid into three residues (tail `OL`/`MY`, head `PC`/`PGR`, tail `OL`/`MY`) that share a resid and sit contiguously. They get one resname (`LIP`) + a shared resid so OST reads them as one residue. Both tails otherwise carry identical carbon names (`C1{n}`) which OST silently **merges** (duplicate atom names in one residue → the 2nd tail's atoms vanish); the fix renames the **second** tail's carbons `C1{n}` → `CB{n}` (kept starting with C so the element still reads carbon). CHARMM/SLipids are already one residue per lipid with distinct sn-1 `C2x` / sn-2 `C3x` names.
- **AMBER water is one giant residue.** The AMBER gro numbers *every* water with the same resid (Lipid17/GROMACS quirk) → MDAnalysis sees one water residue, and OST collapses all the identically named oxygens into a single atom. `tilt_convert` rebuilds water as **one residue per oxygen** (a fresh `Universe.empty`, resids stacked above the lipids) via `mda.Merge(lipids, wu.atoms)`. Harmless for CHARMM/SLipids (already per-molecule). Ions dropped. (Do **not** use `mda.Merge` on the raw water — that was the original bug that lumped all 17k waters into resid 128.)
- Bilayer is assumed already whole & centred in z (cluster trjconv output); no re-centring. The per-frame box **is** written into the DCD (`merged.dimensions = u.dimensions`) — the no-tile analysis runs `PBC=False` and ignores it, but the PBC-tiling cross-check below needs the cell vectors.

**Method (matches Khelashvili 2013, verified against paper + SI + `lipid_analysis.py`):** the lipid **director** t = geometric midpoint of the phosphate P and the backbone glycerol **C2** → COM of the **last three carbons of each chain** (six atoms; SI Fig. S2). Tilt θ = angle(t, membrane normal). χ from the PMF fit `−k_BT ln[P(θ)/sin θ] = (χ/2)θ²`, χ = 2×curvature (`FitTiltDistribution`). **χ is per-lipid in k_BT/rad², with NO area normalisation** — `ExtractTiltAndSplayModuli` uses `lipid_area` only for the *splay/bending* modulus. `tilt_modulus.selections()` gives, per lipid: head `aname=P,C2` (AMBER `P31,C2`; the library's mass-weighted COM differs from the true geometric midpoint by <1 Å, negligible over the ~18 Å director), tail = last-3 carbons of each chain (`C2x,C3x` for CHARMM/SLipids; `C1x,CBx` for the renamed AMBER tails), with `TERM` = 18 (DOPC) / 14 (DMPx).

**Normal source & a sampling gotcha.** The paper uses the *global* bilayer z for its flat patches; `ost_pymodules` uses the *local* water-density interface normal (the general formulation). For these flat 128-lipid / 64 Å patches they converge. But the local normal is only clean if the interface is well sampled: a coarse trajectory stride undersamples the density → noisy normals → inflated tilt → **suppressed** χ (stride-20 gave ~11; full frames give ~14, matching a global-z cross-check of ~13.6). Run production at `--stride 1` (`--density-stride 10` is enough for the average interface); `within_size_normals=10` on the *smoothed* density surface is fine (unlike raw phosphate points, which need ≥15).

**PBC unit-cell tiling is NOT needed here (validated).** The library's example replicates the unit cell to its neighbours (and computes tilts only for the central cell) "to avoid boundary effects on the interfaces and hence on the normal vectors" — because its system is a *curved hexagonal phase*. For a flat bilayer the director is intramolecular and the normal is ≈z everywhere, so a single-cell (non-tiled) interface gives the same normals. Directly checked with the example's exact procedure (`ExtendTrajectoryToNeighboringUnitCells` 2×2 in-plane → `WrapTrajectoryInPeriodicCell` around the central cell → `do_tilt` bool prop on central-cell lipids only): CHARMM DMPC χ = 14.03 (no tile) vs 14.10 (tiled) — a 0.5 % shift, within replicate scatter. So the pipeline runs **without** tiling; the box is still carried in the DCD so tiling can be switched on. `tilt_tiled_validate.py` (kept in the job scratch, not committed) is the cross-check script.

**Splay is skipped.** `tilt_modulus.analyze()` calls the library's tilt pieces directly (`GetBoundaryBetweenViews` → `AssignNormalsToLipids` → `AnalyzeLipidTilts` → `FitTiltDistribution`), not the `AnalyzeLipidTiltAndSplay` wrapper, because we only need tilt and the wrapper's splay step has a bug (`AnalyzeLipidSplays` calls `GetBoolProp('')` with no guard, and needs per-cell chain names) irrelevant here. The library source is left unmodified.

**Running it.** `run_tilt.sh` loops `{ff}×{lipid}×{rep}`: convert → compute χ (appended to `data/tilt_moduli.json`, keyed `{ff}_{lipid}_{rep}`) → delete the bulky DCD (keep the small `.pdb`). Resumable; `FRESH=1` starts the json clean; `FFS`/`LIPIDS`/`REPS`/`STRIDE`/`DENS_STRIDE` env vars subset it. `plot_tilt_modulus.py` (numpy+matplotlib) aggregates to `data/tilt_moduli_summary.json` and a grouped bar chart `plots/tilt_modulus.png` — lipids on x, force fields as `palette` colours, error bars = **± SD across the per-replicate χ** (the project's replicate-spread convention). The tilt angle is in **radians** and χ natively in **k_BT/rad²**; since χ is an energy per rad², the chart's **primary (left) axis is now kJ/mol/rad²** = χ·RT at **T = 310 K** (RT = 2.577 kJ/mol), with the k_BT/rad² scale kept on the right-hand twin axis. Both units are stored per system in the summary json (`chi_kT`/`chi_kJ_per_mol`). Sanity ranges: DMPC ≈ 14, DOPC lower (unsaturated, softer) ≈ 11, CHARMM/SLipids DMPG ≈ 13–15 — all in the literature ~10–15 k_BT/rad². **AMBER DMPG is a genuine outlier at χ ≈ 20–22** (reproducible across all 3 reps; confirmed real, not an edge artifact, by the tiled cross-check 21.3→21.9) — a real force-field effect (anionic PG + Na⁺), not a bug.

## Lipid tilt modulus, second method: Lipidator toolkit (`make_director.py` + `make_lipidator_index.py`)

An independent cross-check of the tilt modulus using the **Lipidator toolkit** (Allolio/Harries, `~/software/lipidator-toolkit`; ReSiS method, `resis` binary). Unlike `ost_pymodules` it reads GROMACS **xtc natively** (`resis traj.xtc library.ldx index.ndx [wtc]`) and reports the tilt modulus **area-normalised in kt/nm²** (not the per-lipid k_BT/rad² of `ost_pymodules`; the two relate as κ[k_BT/nm²] = χ[k_BT/rad²]/A_lipid, which agrees to ~10 % — a mutual validation).

The tool reads **only the xtc** (coordinates + atom count — no names/residues), so the topology is defined entirely by two files, and **AMBER's 3-residues-per-lipid layout is irrelevant** to it:
- **Index (`data/lipidator_{ff}_{lipid}.ndx`, `make_lipidator_index.py`)**: one GROMACS group `[ LIPID ]` (name must match the director) listing the **1-based global index of each lipid's first atom**. Single-residue ff → the residue's first atom; AMBER → first atom of each contiguous residue-triple (tail-head-tail).
- **Director (`.ldx`, `make_director.py`)**: per-lipid `[P/head][1]`, `[CHAIN1/tail][2]`, `[C2/surface][3]`; entries are `(position, mass)` with **position 1-based within the lipid counted from its first atom** and mass an element letter (→ isotope mass) or a float. The tool computes atom = (position−1)+(ndx−1); director = COM(head)→COM(tail). Recipe (matched to the shipped CHARMM lib, verified to reproduce its DMPC/DOPC offsets exactly): head = phosphate + glycerol C2 + both carbonyls + first two acyl carbons of each chain; tail = last three acyl carbons of each chain; surface = head (element mass) + tail (weight 5.0). Force-field atom names: CHARMM/SLipids `P`,`C2`,`C21`/`C31`,`C2x`/`C3x`; AMBER `P31`,`C2`,`C11`/`C21`,`C1x` (per tail residue). **Leave two blank lines after each lipid block.**
- The shipped libraries were incomplete for our lipids: `charmm.ldx` had DMPC/DOPC but **not DMPG**; `slipids.ldx` had only POPC/BMP/POPG. `make_director.py` appends the missing entries (CHARMM DMPG; SLipids DMPC/DOPC/DMPG) and writes `amber.ldx` (DMPC/DOPC/DMPG); idempotent, and `--check-charmm` re-verifies the recipe against the shipped CHARMM offsets. SLipids DOPC needs its own offsets (its atom order differs from CHARMM; DMPC/DMPG orders are identical).
- **Running it:** `run_lipidator.py` (stdlib only) runs `resis` over all 9 systems × 3 reps, parses the `Bilayer Tilt: kappa … kt/nm²` (and APL) from stdout, and writes `data/lipidator_moduli.json` (per-rep) + `data/lipidator_moduli_summary.json` (mean ± SD across reps). `plot_lipidator.py` (numpy+matplotlib, `palette`) → grouped bar chart `plots/lipidator_tilt_modulus.png` (lipids × force fields, error bars = SD across reps); it also **regenerates the summary json in both unit systems** (`tilt_kt_per_nm2`/`tilt_kJ_per_mol_nm2`, conversion ×RT at 310 K) from the per-rep json without rerunning `resis`. The chart's **primary (left) axis is kJ/mol/nm²** (= κ·RT at T = 310 K), with the native k_BT/nm² scale kept on the right-hand twin axis.
- **Results** (κ_θ, kt/nm², mean ± SD over 3 reps): CHARMM 14.6/21.1/19.4, AMBER 15.2/22.1/47.3, SLipids 13.9/21.6/28.1 for DOPC/DMPC/DMPG — tracking the `ost_pymodules` per-lipid results after ÷area (DOPC softest, AMBER DMPG stiffest).
- **Duplicate-block gotcha:** `LoadIndices` iterates *every* director entry and matches each against the index group, so a **duplicated `#LIPID` block in a `.ldx` double-counts that lipid** (n_lipids doubles → APL halves → the area-normalised κ doubles, silently). A merge had left two identical `#DMPC` blocks in `charmm.ldx` (→ CHARMM DMPC read 42 instead of 21); de-duplicated. Keep exactly one block per lipid per library.
- **CHARMM DMPG segfault (fixed):** `resis` crashed (EXC_BAD_ACCESS at `instafit.cpp:416`, `c->size()` with `c=GetCenters()==NULL`). Root cause was a one-character typo in the shipped `charmm.ldx`: the DMPIP2 block's group header was `" [C2][3]"` with a **leading space**, which makes `ReadTopology`'s `[]`-tokenizer read the group id as `"C2"` (not the digit `3`) → `READ_FAIL`; `LoadLibrary` then `break`s at the first failed block, so **every lipid after DMPIP2 (incl. the appended DMPG) never loads** → the `[ DMPG ]` index matches nothing → `centers` empty → `GetCenters()` NULL → null deref. Removing the leading space fixes it (CHARMM DMPG = 19.4 kt/nm²); CHARMM DMPC/DOPC were unaffected because they precede DMPIP2. Lesson: keep director group headers flush-left, no leading whitespace.
- **Build note:** the toolkit no longer compiles as-shipped on current Apple clang (21.x) — `trjflib/minimath.hpp` illegally does `namespace std { struct tuple {...} }`, which now clashes with the real `std::tuple` pulled in via `<string>` ("reference to 'tuple' is ambiguous"). The `2112d9e` "shims" commit on the toolkit's master fixes this; build with `cmake -S . -B build && make -C build` (CommandLineTools `c++`, Eigen/Boost from conda base). The pre-existing `resis` binary already works, so a rebuild is only needed if recompiling.

## Conventions that span multiple files

- **Force-field color scheme is fixed everywhere and centralized in `analysis/palette.py`** (imported by all three scripts — don't hard-code hexes): a colour-blind-friendly blue/green/gold set — CHARMM = blue `#2171b5`, AMBER = green `#0f7d3b`, SLipids = gold `#d4a017`. Each also has a matching light→dark sequential colormap (`palette.CMAPS`) for the 10-replicate `close_pullx` gradients; the gold ramp deliberately stops short of white so light replicates stay visible. The trio was checked with the dataviz colour-blindness validator (worst adjacent CVD ΔE 16.9) — re-validate if you change it, since a brighter yellow collapses onto green under red/green CVD. (The old black/red/green was an xmgrace-compatibility artifact, now retired.)
- **Data-file naming is load-bearing** — the scripts parse it, there is no manifest. `ff` ∈ {`charmm`, `amber`, `slipids`}, `lipid` ∈ {`DOPC`, `DMPC`, `DMPG`}:
  - `{ff}_{lipid}_close{1..10}_pullx.xvg` — 10 "close" (pore-closing) replicates.
  - `{ff}_{lipid}_profile.xvg` — full 100 ns PMF; `{ff}_{lipid}_part{1..5}_profile.xvg` — five consecutive 20 ns windows; `{ff}_{lipid}_20-100_profile.xvg` — an 80 ns window.
  - `plot_range_vs_time.py` reads the sampling window straight from the `gmx wham` `-b`/`-e` flags embedded in each profile's `.xvg` header comments.
- **`.xvg` parsing**: every script has its own tiny loader that skips lines beginning with `#`, `@`, or `&` (comment/xmgrace-metadata) and takes columns 0 and 1.

## Visualization (`analysis/cylinder_pml.sh`)

Run from a run directory; reads the cylinder geometry out of the newest `slurm.*.err` and writes `cyl_style.pml` for PyMOL. Example configurations for every ff/lipid pair live in `snapshots/*_example.gro` — use them to check residue/atom names.

Force field and lipid come from the `ff_lipid` directory name, but on the cluster the run directory is nested several levels below it (umbrella windows, close replicates), so the script **walks up the path** to find it rather than reading the parent — stopping at a directory named `Simulations`, above which it won't look. Both halves must parse as a known force field *and* lipid, so intermediate dirs that merely contain an underscore (`run_2`, `window_5`) are not mistaken for it. `cylinder_pml.sh <ff> <lipid>` overrides detection entirely.

**The residue-name matrix each force field needs** (all verified against `snapshots/`):

| | water | ions | lipid residue(s) |
|---|---|---|---|
| CHARMM | `TIP3` | `SOD` `CLA` `MG` `CAL` | one residue: `DOPC`/`DMPC`/`DMPG` |
| AMBER | `TP3` | `Na+` `Cl-` `MG` `CA` | head `PC` (DMPG: `PGR`) + tail `OL` (DOPC) / `MY` (DMPC, DMPG) |
| SLipids | `SOL` | `NA` `CL` `MG` `CA` | one residue: `DOPC`/`DMPC`/`DMPG` |

- **Hiding tails** is the one genuinely force-field-dependent step. AMBER splits each lipid into head and tail residues, so it's just `resn OL`/`resn MY`. CHARMM/SLipids put the whole lipid in one residue, so the tails are selected by atom name: `name C2*+C3* and not name C2+C3+C21+C31` — the exclusion matters, because glycerol `C2`/`C3` and ester carbonyls `C21`/`C31` match the wildcard but live in AMBER's *head* residue. Hydrogens are then added by bond (`hydro and neighbor ...`), since CHARMM tail-H names (`H2R`,`H2X`,…) collide with glycerol `HS`/`HX`/`HY`. Verified in PyMOL: this hides exactly the same atom counts as AMBER's residue selection (DOPC 12800, DMPC/DMPG 10240) and leaves the same heads visible (4864/4864/3968).
- **PyMOL gotchas**: `+`/`-` in AMBER's `Na+`/`Cl-` are selection-list characters and must be backslash-escaped (`resn Na\+`) — quoting does *not* work for `+`. `elem` selections are useless here: PyMOL assigns no elements when loading a `.gro`.

## Simulation setup details (`setup_scripts/`, `setup_files/`)

- `setup_pull.sh` infers `FF` and `LIPID` from the **working directory name** (must be `ff_lipid`, e.g. `amber_DOPC`). It builds the `pull.ndx` index groups: `MEMB`, `SOLV`, `tail` (pull reference), and `ONP` (all O/N/P atoms — the pulled polar group). AMBER needs per-lipid residue-name handling (via bash associative arrays) because it splits head/tail into separate residues; CHARMM/SLipids select by lipid resname directly.
- MDP files come in `pull_{ff}.mdp` (steered, `pull-coord1-rate` nonzero) and `umbrella_{ff}.mdp` (`pull-coord1-init`/`-k` are `SETME`/`SETKTOO` placeholders filled per window). Force-field variants differ mainly in nonbonded cutoffs (`rcoulomb`/`rvdw` 1.2 vs 1.0, `vdw-modifier` force-switch vs potential-shift, `DispCorr`).
- The chain-coordinate CV is configured via `SLICE_COORD_*` environment variables in the `submit_*.sh` scripts (slice count, cylinder radius, frozen pore center X/Y), not through the MDP.

## `topology_wrangling/` (gitignored working dir)

`setup_scripts/reorder_dopc.py` reorders per-molecule atoms in a GROMACS `.gro` file to match the atom order in an `.itp` topology (matching by unique atom name), then renumbers the global index column. Only touches DOPC residues; leaves everything else in place.

## Equilibrium summary table for the manuscript (`make_equilibrium_table.py`)

`analysis/make_equilibrium_table.py` (numpy + stdlib) parses every **equilibrium**-derived observable in `data/` and emits a drop-in LaTeX table `data/equilibrium_summary_table.tex` (needs `\usepackage{booktabs,multirow,amsmath}`), one row per `(lipid, force field)`. The pore branches (PMFs, cylindrical pore densities, closure trajectories) are excluded — not equilibrium quantities. Grouped columns:

- **lipyphilic** (from `lipprops_*.npz`): APL (Å²), P–P thickness `d_HH` (nm, ÷10 from the Å npz), inter-leaflet registration, lateral diffusion `D` (×10⁻⁷ cm²/s, from the `_D` key), and chain-averaged `⟨S_CC⟩`.
- **g_lomepro**: chain-averaged `⟨−S_CD⟩` (mean of col 2 of the `_scd_sn{1,2}.dat` files, both tails pooled).
- **tilt modulus**: `χ` (ost_pymodules, kJ/mol/rad², from `tilt_moduli_summary.json`) and `κ_θ` (Lipidator/ReSiS, kJ/mol/nm², from `lipidator_moduli_summary.json`).

Every cell is **mean ± population-SD across the 3 replicates** (each rep first reduced to one scalar — mean over frames/lipids/carbons/chains — per the project's replicate-spread convention; the two tilt JSONs already apply it). Missing systems are reported at the end (flagged as "likely not pulled from the cluster"). **Design notes / flags:** there is **no "pure MDA" column** — every MDAnalysis-based equilibrium observable also goes through lipyphilic (or its leaflet assignment), and tilt-convert's MDA use just feeds OpenStructure; the order-parameter columns are **chain-averaged scalars** (lossy — the full per-carbon profiles live in `plots/lipprop_{order_parameter,scd}.png`); **registration is near-zero** here (it measures domain registration in phase-separating mixtures, so it is uninformative for these single-component bilayers but included for completeness); the equilibrium **`gmx density` profiles** are equilibrium data but z-distributions with no replicates, so they are not table-able scalars.
