# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this project is

Molecular-dynamics study of lipid-membrane pore formation and stability, comparing three force fields — **CHARMM**, **AMBER**, and **SLipids** — across lipids DOPC, DMPC, and DMPG. Pores are driven along a "chain coordinate" collective variable ξ (`pull-coord1-geometry = pore-slices`) that is only available in a custom GROMACS fork (`gromacs-chain-coordinate`), not stock GROMACS. The repo holds the simulation setup machinery, the resulting `.xvg` data, and the Python plotting scripts.

## Pipeline (end to end)

1. **Setup** (`setup_scripts/`, `setup_files/`): build index groups + `.tpr` files for a run.
2. **Simulate on an HPC cluster** via SLURM (`submit_*.sh`) — steered pulling, then umbrella-sampling windows. Produces `*_pullx.xvg` (COM position vs time) and, after `gmx wham`, `*_profile.xvg` (PMF).
3. **Analyze** (`analysis/`): matplotlib scripts read `data/*.xvg` and write PNGs to `plots/`.

Steps 1–2 run on a cluster and cannot be executed here (they hard-code module loads, a `/u/epoppleton/...` GROMACS path, and `sbatch`). Only step 3 runs locally.

## Running the analysis scripts

```bash
python3 analysis/plot_pmf.py            # DOPC/DMPC/DMPG PMF profiles as one 1x3 figure, each curve min-zeroed
python3 analysis/plot_close_pullx.py    # per-lipid ξ(t) trajectories, one panel per force field
python3 analysis/plot_range_vs_time.py  # per-lipid PMF energy range vs sampling time / start time
```

`plot_pmf.py` writes a **single** `plots/pmf_profiles.png` — a 1×3 grid with the lipids across the columns (shared y-axis), the three force fields overlaid and min-zeroed in each panel (the five 20 ns partials drawn faintly behind), a shared force-field colour-key legend, and force fields/lipids with no `*profile.xvg` simply absent from their panel. `plot_close_pullx.py` / `plot_range_vs_time.py` still loop over `LIPIDS = ["DOPC", "DMPC", "DMPG"]` and write one output (or output pair) per lipid, suffixed with the lipid name (e.g. `close_pullx_DOPC.png`); `plot_range_vs_time.py` skips lipids with no `*profile.xvg` data.

Requires only `numpy` + `matplotlib`. Each script derives paths from its own location (`analysis/` → `data/`, `plots/`) via `Path(__file__)`, so run them from anywhere. There are no tests, linter, or build step.

## Equilibrium lipid-property analysis (`lipid_properties.py` + `plot_lipid_properties.py`)

A second, independent analysis branch (not part of the PMF/pulling pipeline) computes bulk membrane properties from the equilibrium MD runs with **lipyphilic**. It is split into a slow compute step and a fast styling step so the analysis need only run once:

```bash
# 1. compute (cluster-side, in the 'lipid64' conda env; slow) -> data/lipprops_*.npz
conda run -n lipid64 python analysis/lipid_properties.py
# 2. plot (anywhere, numpy+matplotlib only) -> plots/lipprop_*.png
python3 analysis/plot_lipid_properties.py
```

- **Input layout**: `~/Simulations/{ff}_{lipid}/eq{1,2,3}/` each holding `memb.gro` + `inbox.xtc`, **both waters-stripped** (override the trajectory name with `--traj`). Override the root with `--sims-root`, or subset with `--forcefields/--lipids/--reps`.
- **Parallelism**: lipyphilic 0.12.1's analyses are all `serial`-only (`get_supported_backends() == ('serial',)`), so MDAnalysis's per-analysis `backend="multiprocessing"` isn't available. Instead the 27 `(ff, lipid, rep)` trajectories are independent single-core jobs farmed across a `multiprocessing` pool with `--nprocs N` (capped at the number of trajectories found; 1 core each). Aggregation is keyed by replicate, so out-of-order completion is fine — parallel output is bit-identical to serial. The script pins BLAS to one thread per worker (`OMP_NUM_THREADS=1` etc., set before numpy import) to avoid oversubscription. Request ≈`--nprocs` cores; e.g. `--nprocs 9` ≈ 3 min, `--nprocs 27` ≈ 1 min for the full set.
- **Topology is `memb.gro`, not `md.tpr`** — both `memb.gro` and `inbox.xtc` have waters stripped (faster universe setup / less to read), so their atom sets match; `memb.gro` is the topology for **both** the MDAnalysis universes and g_lomepro's `-s`. This also sidesteps MDAnalysis's inability to read GROMACS 2026.3's tpx v138 `md.tpr`. (Locally the only equilibrium trajectory present is `charmm_DMPC/eq1`, whose topology can also be stood in by a matching `snapshots/*.gro`.)
- **AMBER `memb.gro` needs residue renumbering first (for the order parameter only)**: GROMACS gives a Lipid17 lipid's two tail residues (`OL`/`MY`) the *same* residue id, and they sit adjacent in the file, so MDAnalysis merges them into one lumpy residue — which breaks the per-tail `reshape` in the S_CC calculation. Renumber `memb.gro` so every tail is a unique residue before running. Only the order parameter is affected: the phosphate-keyed analyses (leaflets/APL/thickness/registration/MSD) stay correct because the heads remain distinct, and CHARMM/SLipids (one properly-numbered residue per lipid) are fine as-is. `scc_profile()` guards this with an up-front carbons-per-residue check that raises an actionable error instead of an opaque reshape failure.
- **Five properties** keyed off one phosphate selection `name P P31` (CHARMM/SLipids name it `P`, AMBER `P31`): leaflets/APL/thickness/registration/MSD via lipyphilic (`AssignLeaflets`, `AreaPerLipid`, `MembThickness`, `Registration`, `MSD`). The order parameter is computed directly in `scc_samples()` (not via lipyphilic's `SCC`) so it can keep the **per-carbon** values: for each C–C bond it takes S_CC = ½⟨3cos²θ−1⟩ with the bilayer normal along z (lipyphilic's default). It stores the *full* per-carbon array — every chain at every frame, pooled over both tails — in the npz (this is the ~100 MB file). Tails: CHARMM/SLipids split the two tails by atom name (`C2x` vs `C3x`, N=18 for DOPC else 14); AMBER pools its two `OL`/`MY` tail residues. Carbons within a residue are sorted by acyl number so CHARMM (ascending in the topology) and AMBER (descending) give the same head→tail profile. Averaging over carbons reproduces lipyphilic's per-chain SCC exactly (validated). **The S_CC npz is still computed and kept as raw data, but nothing plots or tabulates it any more** — the per-carbon *profile* is a per-bond-parity artifact (see the plots section) and the scalar is redundant with S_CD, so both the profile plot and the `⟨S_CC⟩` table column were removed.
- **MSD needs unwrapped coordinates**: lipyphilic's `MSD` assumes no PBC jumps, but the trajectories are wrapped, so a boundary crossing becomes a ~box-length jump that inflates the MSD by ~30–50× (a `dt` red herring — MDAnalysis's `u.trajectory.dt` matches `gmx check` exactly). `analyse()` adds an MDAnalysis `NoJump` transformation *after* the four phosphate/leaflet analyses (which need in-box coordinates for their PBC-aware Voronoi/leaflet logic) and *before* MSD, which is run last. This alone takes DMPC's fitted D from a spurious 5e-7 to a physical ~9e-8 cm²/s.
- **`data/lipprops_{prop}.npz` layout** (one file per property): the three distribution properties (`area_per_lipid`, `memb_thickness`, `registration`) store pooled samples under key `{ff}_{lipid}` plus per-replicate `{ff}_{lipid}_eq{n}`. `memb_thickness`/`registration` are one value per frame (1-D). `area_per_lipid` is **2-D `(n_frames, n_lipids)`** per replicate (frames along axis 0) — the histogram flattens it, but keeping the frame axis lets the trajectory plot show a per-frame mean±SD over lipids; this is the ~60 MB file. `order_parameter` stores `{ff}_{lipid}_carbons` (acyl carbon numbers) + one full per-replicate array `{ff}_{lipid}_eq{n}` of shape `(n_chain_frames, n_carbons)` — the complete per-carbon S_CC for every chain and frame (per-rep only, no pooled duplicate; this is the ~100 MB file, retained as raw data even though nothing plots/tabulates S_CC now). `lateral_diffusion` stores `{ff}_{lipid}_lagtimes`, `_msd` (reps×lag), `_D`, `_Dsem`. (`area_per_lipid` is also ~60 MB — a genuine per-lipid-per-frame distribution.)
- **APL projection maps** — for replicate 1 only, `lipid_properties.py` also renders **upper-leaflet** APL-projected-onto-the-membrane-plane heatmaps to `plots/lipprop_aplproj_{ff}_{lipid}_{avg,final}.png`: `avg` = mean APL over the trajectory, **linearly** interpolated between lipids (a smooth local-APL field); `final` = the last frame, **nearest-neighbour** interpolated so each cell takes its closest lipid's area — i.e. the **Voronoi tessellation** lipyphilic uses to compute APL (discrete per-lipid tiles, on a 1 Å × 1 Å grid). Only one leaflet is shown because APL is defined by a *per-leaflet* Voronoi: tessellating both leaflets' phosphates together gives cells that aren't the APL cells (rasterised cell area correlates with APL at ~0.2 vs ~0.98 for a single leaflet — an opposite-leaflet phosphate nearby in xy clips a lipid's tile, producing the giveaway "small tile, near-maximal APL"). lipyphilic's `AreaPerLipid.project_area()` hard-wires linear interpolation (a single frame comes out smoothly blended, *not* tessellated) and projects both leaflets, so the script drives `lipyphilic.plotting.ProjectionPlot` directly to pick the method and filters to `leaflets == 1`. Lipid positions are the phosphate xy (one per lipid — the same selection APL's Voronoi is built from), so no COM unwrap / bond guessing is needed. Runs *inside* the analysis (needs the trajectory, not just the npz) and *before* the NoJump transform (coords must still be in-box); rendering is headless (`MPLBACKEND=Agg` forced before lipyphilic imports pyplot); any projection failure is downgraded to a warning so it never costs the numerical results.
- **Lipid-trajectory plot** — also rep 1 only, `save_lipid_trajectories()` writes `plots/lipprop_lipidtraj_{ff}_{lipid}.png`: the in-plane (xy) path of every **upper-leaflet** phosphate over the whole trajectory, one per lipid (the `PHOSPHATE` selection), each a distinct colour — a visual for lateral diffusion (MSD) and packing (APL). Paths are **PBC-unwrapped** here (cumulative minimum-image steps) so each is a continuous walk rather than jumping across the box (done explicitly, so it doesn't depend on the NoJump ordering). The ~64 upper-leaflet lipids exceed matplotlib's 10-colour default, so colours come from `palette.evenly_spaced_cmap(n)` — `n` hues evenly spaced around the wheel at *constant HLS lightness* (distinct without a light→dark ramp implying order; `palette.evenly_spaced_colors`/`evenly_spaced_cmap` are the reusable helpers). A dot marks each lipid's final position.
- **Plots** are 1×3 lipid panels (DOPC/DMPC/DMPG) with the three force fields overlaid in the `palette.py` scheme:
  - the three distribution properties → overlaid density histograms (`plots/lipprop_{prop}.png`), each force field's pooled mean marked with a dashed vertical line in its colour. `memb_thickness` (d_HH) is plotted **in nm** (`scale=0.1`, x-label `$d_\mathrm{HH}$ (nm)`) — the samples are rescaled Å→nm, not just relabelled. Each also gets a **per-frame trajectory** figure (`plots/lipprop_traj_{prop}.png`) for replicate 1: a 3×3 grid with lipids across columns and force fields down rows, all nine panels sharing the y-axis. `area_per_lipid` (per-lipid) shows the per-frame mean±SD over lipids; the whole-membrane `memb_thickness`/`registration` show their single per-frame value. x-axis is frame index. **Each panel marks the pymbar `t0`** for that rep-1 run (dashed line + shaded discarded burn-in + `t0=… ns` label, read live from `equilibrium_timeseries_stats.json` via `_t0_rep1`; frames→ns at 0.2) — so the discarded burn-in is visible, and the AMBER/SLipids **DMPG** thickness panels dramatically show the ~400–480 ns rise pymbar discards (t0 shading covers most of the panel) while well-behaved systems sit at t0≈0;
  - a **d_HC companion to the d_HH histogram** (`plot_core_thickness_histograms()` → `plots/lipprop_core_thickness.png`): the same 1×3 overlaid density-histogram layout, in **nm**, built from the per-frame **lipyphilic** `d_HC` in `core_thickness.npz` (`{ff}_{lipid}_lipy_rep{r}`, the 3 reps pooled — the only d_HC metric stored per frame; the density metric is 3 scalars/system and can't form a distribution). Uses **1.5× wider bins** (27 vs the 40-bin default) since the core-thickness distributions are otherwise jagged;
  - `order_parameter` (S_CC) → **the per-carbon profile plot was dropped** (the npz is still computed and stored — see below — just no longer plotted or tabulated). Reason (investigated): the per-carbon S_CC profile shows an **even/odd sawtooth** because S_CC is a *per-C–C-bond* quantity — consecutive bonds of an ordered, tilted chain sit at alternating angles to the normal. When the plot pools sn-1 and sn-2, the two tails' sawtooths are ~anti-phase and *cancel* for CHARMM/AMBER DMPC/DMPG (pooled jag ~0.03, looks smooth) but stay *in-phase* and add for SLipids (all lipids) and any DOPC (the cis-Δ9 double bond pins both tails to agree in the kink) → pooled jag ~0.15–0.30, visibly jagged. Whether the tails land anti-phase or in-phase is an arbitrary per-force-field geometric accident with **no physical meaning** — it is *not* a selection bug (CHARMM/SLipids share identical `C2x`/`C3x` naming + sort) and *not* a phase difference (mean chain tilt ≈30° and the smoothed-director order high & smooth for all systems; both fluid Lα). The NMR-comparable smooth per-carbon profile is the g_lomepro **S_CD** one below (`plots/lipprop_scd.png`), which is what we keep; the scalar `⟨S_CC⟩` (mean over carbons) is robust but redundant with S_CD, so it was dropped from the summary table too;
  - `lateral_diffusion` → a log-log MSD-vs-lag-time curve (mean ± replicate spread) with an inset (linear) bar graph of the fitted diffusion coefficient. The inset auto-places into whichever corner (top-left or bottom-right) the MSD curve overlaps least — computed by projecting the curve into log-log axes-fraction coordinates and counting points inside each candidate rectangle — so it lands above low curves (DMPC/DMPG) and below high ones (DOPC).

  Panels/force fields with no `.npz` data are skipped.

## S_CD order-parameter index files for g_lomepro (`make_order_index.py`)

`lipid_properties.py` computes **S_CC** (C–C bond vs bilayer normal). The more NMR-comparable **S_CD** (deuterium / H–C–H) order parameter is instead computed cluster-side with **g_lomepro** (`-order`), which reads its acyl carbons from a GROMACS `.ndx`. `analysis/make_order_index.py` generates that `.ndx` (numpy + stdlib only):

```bash
python3 analysis/make_order_index.py                           # every traj/*.gro -> data/order_{ff}_{lipid}.ndx
python3 analysis/make_order_index.py traj/charmm_DOPC.gro      # a subset
python3 analysis/make_order_index.py md.gro --ff amber --lipid DOPC
# then copy each cluster-side as {ff}_{lipid}/lomepro.ndx (see analysis/README.md Step 0c)
python3 analysis/make_order_index.py md.gro --ff amber --lipid DOPC
```

- **g_lomepro's index contract** (verified against its source, `order.c`/`g_lomepro.c`, not just the help text): it reads the **sn-1 chain** group then the **sn-2 chain** group, each listing that chain's carbons *per lipid, in chain order*, concatenated lipid-after-lipid (`idorder1[i + j*order_atom_num1]`). S_CD for carbon `i` uses neighbours `i-1`/`i+1` (`for(i=1; i<N-1; i++)`), so the **first and last atom of each chain get no value** — they are neighbours only. The script therefore makes the **carbonyl the first atom** of each chain, so a C1(carbonyl)..C14 chain yields S_CD for **C2..C13** (matches the Gapsys 2013 paper's C2/C7/C13 labels; `reference/gapsys2013computational.pdf`).
- **Double bonds** (`-unsat`): each needs a separate group of **exactly two atoms per lipid** — the two sp² carbons `Ci` then `Ci+1`. DOPC is di-oleoyl (18:1 cis-Δ9) → `-unsat 2` and two double-bond groups (`sn1_double_bond` at C9=C10, then `sn2_double_bond`); DMPC/DMPG are di-myristoyl (14:0) → `-unsat 0`, no double-bond groups. Because all three lipids are symmetric, the sn-1/sn-2 assignment is immaterial.
- **Atom naming** (verified geometrically against `snapshots/`): CHARMM/SLipids use one residue — sn-1 `C21`(carbonyl)..`C2N`, sn-2 `C31`..`C3N` (N=18 DOPC / 14 DMPC/DMPG), DOPC double bond `C29=C210` / `C39=C310`. AMBER Lipid17 splits each lipid into tail–head–tail: the two carbonyls live in the head (`PC`/`PGR`) as `C11` (chain before the head) and `C21` (chain after); tail residues (`OL`/`MY`) name carbons `C1x` = fatty-acid carbon `x` (`C12..C1N`), double bond `C19=C110`. Each tail is paired to its carbonyl by nearest-distance from the tail's `C12`.
- **Robust residue splitting**: raw Lipid17 `md.gro` numbers *every* residue `1`, so sn-2 of one lipid and sn-1 of the next merge into one 100-atom `OL`/`MY` block. The script ignores resid and starts a new residue whenever the resname changes **or an atom name repeats** — validated to split those merged blocks correctly (including lipids that begin mid-block). Index serials are 1-based file positions (= GROMACS serials). The default input is the **full-system `traj/{ff}_{lipid}.gro`** (same as `make_density_index.py`/`make_tail_index.py`), even though g_lomepro reads the waters-stripped `inbox.xtc`: the lipids are the **leading contiguous block** of the gro (water/ions follow), so lipid serials coincide and the index is **byte-identical** to one built from `memb.gro` (verified for all 9 systems). `generate()` asserts that layout (`membrane == 1..N`) and exits otherwise. The renumbered gros used for MDAnalysis's S_CC are **not** needed here.
- The `.ndx` also carries a `Membrane` (all lipid atoms, for g_lomepro's lipid selection) and `Phosphates` (`name P P31`) group. The script prints the detected ff/lipid, lipid count, per-chain atom count, the resulting S_CD carbon range, the `-unsat` value, and the exact group-selection order g_lomepro will prompt for.
- **Running g_lomepro** (built into `lipid_properties.py`): by default the pipeline script runs *both* the lipyphilic npz analysis and, as a second step, the g_lomepro S_CD analysis. `--skip-lomepro` / `--skip-lipyphilic` run just one half; the g_lomepro half needs only numpy + the binary (the MDAnalysis/lipyphilic imports are optional, guarded behind `_HAVE_LIPYPHILIC`), so it can run on a bare node with `--skip-lipyphilic`. For each `{ff}_{lipid}` it reads the **pre-built** `{ff}_{lipid}/lomepro.ndx` — a *preprocessing* artifact made once by `make_order_index.py` (locally, from `traj/{ff}_{lipid}.gro`) and copied next to the `eq{rep}` dirs; a system without one is **skipped** with an actionable message. `read_order_index()` parses that `.ndx` for the two numbers `generate()` used to return: `-lip_num` = `len(sn1)/TAIL_NC[lipid]` (one chain of carbonyl+C2..CN per lipid) and `-unsat` = 2 iff an `sn1_double_bond` group is present (round-trips exactly against `generate()` for all three ff). Then for every replicate it makes a fresh `eq{rep}/lomepro/` (overwriting any previous one) and runs, from the `eq{rep}` dir, `echo "<groups>" | g_lomepro_static -f inbox.xtc -n ../lomepro.ndx -s memb.gro -lip_num <N> [-unsat 2] -order lomepro/scd.out`. (`-lip_num` = 128 here; the `sn{1,2}_double_bond` groups and `-unsat 2` are added only for DOPC — myristoyl DMPC/DMPG select just `Membrane sn1 sn2`.) It then copies `lomepro/scd.out_AVG_sn{1,2}.dat` → `data/{ff}_{lipid}_{rep}_scd_sn{1,2}.dat` (one file per replicate, kept as separate samples). Binary path defaults to `~/software/g_lomepro/g_lomepro_static` (`--lomepro-bin` to override). g_lomepro (a GROMACS tool) needs `GMXLIB` pointing at GROMACS's data dir; the script sets it in the subprocess env — respecting an existing `GMXLIB`, else deriving it from `gmx` on `PATH` (`<prefix>/bin/gmx` → `<prefix>/share/gromacs/top`).
- **Plotting** (`plot_scd()` in `plot_lipid_properties.py`): reads g_lomepro's `_AVG_sn{1,2}.dat` output, in `data/` as `{ff}_{lipid}_{rep}_scd_sn{1,2}.dat` (columns `carbon_number, mean(-S_CD), sd` — the two data columns are the g_order-style mean and its standard deviation over lipids×frames, **not** the two tails). Carbon number down an inverted per-lipid y-axis, `-S_CD` on x, force fields overlaid, → `plots/lipprop_scd.png` (this is the only per-carbon order-parameter figure now — the S_CC profile was dropped, see above). The two tails are averaged *within* each replicate (justified because for these symmetric di-oleoyl/di-myristoyl lipids the sn-1/sn-2 profiles differ by <0.01, the only non-trivial gap being ~0.03 at the C9=C10 double bond), then the line is the mean over replicates and the band the SD across them — see the error-bar convention below.

- **Error-bar convention (point-estimate plots/tables)**: bands/error bars are a **hierarchical 95% CI** (`analysis/autocorr.py`; see the dedicated section below) that combines each replicate's *within-run* error with the *between-replicate* spread — `SE = √(max(between_sd², within_sem²)/n)`, tight/pooled where replicates agree, honestly wide where they don't. The within-run error is the autocorrelation-limited SEM (`SD/√Neff`, on the pymbar-`t0` production span) for the **per-frame** observables (APL, d_HH, d_HC), and a **block-averaged SEM** for the tilt moduli (χ, κ). **`D` and `⟨−S_CD⟩` keep ± SD across the per-replicate means** — a single fitted scalar / profile per run, no within-run series. (History: the whole project used ±SD-across-reps until this was upgraded; the ±SD reasoning — MD frames are autocorrelated, so a naive pooled-frame CI is pseudoreplication — is exactly *why* the within-run term uses `Neff`, not the raw frame count.) The distribution **histograms** (`area_per_lipid`/`memb_thickness`/`registration`) are the deliberate exception — they show the full pooled-across-reps *distribution*, not a mean ± error.

## Density-profile index files for gmx density (`make_density_index.py`)

`analysis/make_density_index.py` builds a GROMACS `.ndx` per force field / lipid for `gmx density`, from the **full-system (water + ion)** `traj/{ff}_{lipid}.gro` topologies (one replicate's downloaded `md.gro` per system — the canonical full-system gro, *not* the lipid-only `memb.gro` used for lipyphilic; the old `tmp/*.gro` copy is retired, it was byte-identical). Writes `data/density_{ff}_{lipid}.ndx` with a **constant 8-group layout** (so a density loop needs no per-lipid conditionals): `water`, `sodium`, `magnesium`, `calcium`, `phosphorus`, `glycerol_C2`, `midpoint_C`, `terminal_C`. Only the underlying carbon varies by lipid — `midpoint_C` = the upper C=C carbon C9 for DOPC, mid-chain C7 for DMPC/DMPG; `terminal_C` = the last acyl carbon (C18 for DOPC, C14 for DMPx). Both cover both chains.

```bash
conda run -n lipid64 python analysis/make_density_index.py           # all tmp/*.gro
python analysis/make_density_index.py tmp/charmm_DOPC_md.gro         # a subset
```

- **Selections** are built from resname/atom-name masks and written with `MDAnalysis.selections.gromacs.SelectionWriter` (masks, not selection strings, so AMBER's `Na+`/`Cl-` don't trip the parser). Water/ion resnames are auto-detected (`water` = TIP3/TP3/SOL; `sodium` = SOD/Na+/NA; `calcium` = CAL/CA; `magnesium` = MG), which also pins the force field (TIP3→CHARMM, SOL→SLipids, TP3/OL/MY→AMBER).
- **Acyl-carbon naming**: CHARMM/SLipids keep both tails in one residue so a chain position matches `C2{n}`+`C3{n}` (128+128); AMBER's two tail residues (`OL`/`MY`) both use `C1{n}`, so one position matches 256. Glycerol `C2` and phosphate (`P`/`P31`) live in the single residue (CHARMM/SLipids) or the head residue `PC`/`PGR` (AMBER). DMPG carries 128 Na⁺ counterions (`sodium` ≈ 141) vs ≈14 for the neutral PC lipids.
- Empty groups (an ion species absent from a system) are skipped with a warning, since `gmx density` errors on an empty group. Indices are 1-based GROMACS serials from the full-system gro, so run `gmx density` against the matching full-system trajectory (not `inbox.xtc`). Output lands in the gitignored `data/`.
- **Plotting** (`plot_density.py`, numpy+matplotlib): reads `data/{ff}_{lipid}_density.xvg` (gmx density output; columns mapped to group names via the `@ sN legend` header) and draws a 3×3 grid (lipids across columns, force fields down rows) → `plots/density_profiles.png`. Each curve is **peak-normalised** (÷ its own max, so abundant water doesn't dwarf the sparse ions) and each panel's z-axis is **shifted so the `terminal_C` peak is at 0** (the bilayer centre). Colours: water blue, Na⁺ purple, Mg²⁺ green, Ca²⁺ teal, P orange, and the three carbons in greys from black (`glycerol_C2`, head) through mid-grey (`midpoint_C`) to light-grey (`terminal_C`, tail). Mg²⁺/Ca²⁺ (1–4 atoms) are computed in the index but **dropped from the plot** (`GROUPS`) — peak-normalising 1–4 atoms just amplifies noise into the already-busy head-group region.

## Hydrophobic-core thickness d_HC (`make_tail_index.py` + `core_thickness.py` + `plot_core_thickness.py`)

Alongside the phosphate–phosphate thickness `d_HH` (lipyphilic `MembThickness` on `name P P31`, in `lipid_properties.py`), a **hydrophobic-core thickness `d_HC`** is computed by **two independent metrics** so the two can be cross-checked. Inputs are the water-containing `traj/{ff}_{lipid}.{gro,tpr}` + `{ff}_{lipid}{1,2,3}.xtc` (the same set the tilt modulus uses; 9 systems × 3 reps). **Windows differ by metric**: the lipyphilic metric runs over the **full 250 ns trajectory** (equilibration already dropped from the downloaded xtc, so no further truncation is needed); the density metric keeps the **last 50 ns** because that literal window is part of the published method it reproduces.

- **Metric 1 — lipyphilic, first-tail-carbon selector** (`core_thickness.py`, runs locally in `lipid64`; **full trajectory**): `AssignLeaflets` + `MembThickness` keyed on the **first aliphatic tail carbon of each chain** instead of the phosphate — `C22`/`C32` for CHARMM/SLipids (the methylene just past the sn-1/sn-2 carbonyl) and `C12` of each `OL`/`MY` tail residue for AMBER (whose tail residue already starts at that methylene). That plane sits at the polar/apolar boundary, so the leaflet-to-leaflet distance is the core thickness. **Both AssignLeaflets and MembThickness use the same selection** (as the repo's `d_HH` does with the phosphate) so the per-residue `leaflets` array aligns; AMBER's two tail residues per lipid (256 residues) are each assigned by their `C12` z (both tails of a lipid land in the same leaflet, so it's self-consistent). The script **also** runs a second `MembThickness` on the **phosphate** (`name P`/`P31`) over the same full trajectory, giving a **frame-aligned per-frame `d_HH(t)`** (npz key `{ff}_{lipid}_dhh_rep{r}`) alongside the per-frame `d_HC(t)` (`_lipy_rep{r}`) — the raw material for the per-frame decomposition below.
- **Metric 2 — tail mass-density width @ 500 kg/m³** (the reference-paper method): the mass density profile of the hydrophobic tail atoms is a slab centred on the bilayer mid-plane (a two-humped curve with the terminal-methyl trough at z=0, ~800 kg/m³ plateau), and `d_HC` is its **full width where it crosses 500 kg/m³** (outermost crossings, linearly interpolated between slices — `width_at()`). Two sources, which agree to **mean |Δ| ≈ 0.02 nm** (validated):
  - **cluster `gmx density`** (the canonical tool; the fork's tpr can't be read by stock local gmx, so this runs cluster-side). Needs a tail-atom index → `make_tail_index.py`.
  - **local MDAnalysis** (`core_thickness.py`, `tail_density()`): a mass-weighted z-histogram of the same `tails` atoms, per frame centred on the tail COM, converted amu/Å³ → kg/m³ (×1660.539). Runs on `traj/` with no tpr; masses are MDAnalysis-guessed (C 12.011 / H 1.008, matches the tpr masses gmx uses). This is the fallback/cross-check and gives numbers without waiting on the cluster.
- **`make_tail_index.py`** writes `data/tail_{ff}_{lipid}.ndx` with a **`tails`** group (every aliphatic acyl-chain atom of both chains **plus hydrogens** — all-atom, so the kg/m³ scale matches a real tail density and the 500 kg/m³ threshold is meaningful; the polar carbonyl and glycerol/head are **excluded**) and a **`Membrane`** group (all lipid atoms, a centering group for `gmx density -center`). Tail atom set: CHARMM/SLipids take aliphatic carbons `C2{2..N}`/`C3{2..N}` (past the carbonyl `C2 1`/`C3 1`) + **bonded hydrogens found by geometry** (`guess_bonds`, so the differing CHARMM vs SLipids H-naming doesn't matter); AMBER's whole `OL`/`MY` tail residue *is* the aliphatic tail (carbonyl is in the head), so no masking/bond-guessing. The three force fields land on **identical per-lipid atom counts** — 80/lipid for DMPC/DMPG (2 chains × (13 C + 27 H)), 100 for DOPC (2 chains × (17 C + 33 H incl. the 2 double-bond CH)) — an apples-to-apples check. Serials are 1-based file positions from `traj/{ff}_{lipid}.gro` (matches the xtc/tpr order). The script prints the exact `gmx density -dens mass -center -symm -sl 200 -b <t_last50> -n data/tail_{ff}_{lipid}.ndx` command (select `Membrane` to centre, `tails` to output → `data/{ff}_{lipid}_{rep}_taildens.xvg`).
- **`plot_core_thickness.py`** (numpy+matplotlib): reads `data/core_thickness.npz` (metric 1 per-frame `{ff}_{lipid}_lipy_rep{r}`, metric-2-local per-rep `{ff}_{lipid}_denswidth`, and the replicate-mean profile `{ff}_{lipid}_densprof{,_z}`) plus the gmx `*_taildens.xvg` (parsed by **legend**, picking the `tails` column via the `@ sN legend` header — robust to column order after the first cluster run mistakenly output only `Membrane`). Two figures: `plots/core_thickness.png` — 1×3 lipid panels, force fields on x, two d_HC bars per ff (**solid = lipyphilic, hatched = density**; density prefers gmx, falls back to local MDA) with a black dash at `d_HH`, error bars = SD across reps; and `plots/core_thickness_profiles.png` — the tail mass-density profiles per lipid (force fields overlaid) with the dotted 500 kg/m³ line. All `d_HC` (~2.3–2.8 nm) sit correctly below `d_HH` (~3.5–3.85 nm); **AMBER DMPG is the thickest core (~2.8 nm)**, consistent with its outlier `d_HH`/tilt-modulus behaviour elsewhere. The two metrics agree to ~0.01–0.02 nm across all 9 systems (thickness is converged, so the lipyphilic-full-traj vs density-last-50 ns window difference is negligible).

### d_HH → core + headgroup decomposition (`decompose_thickness.py`)

`analysis/decompose_thickness.py` (numpy + matplotlib) splits the phosphate–phosphate thickness into a **tail/core** term and a **headgroup-extension** term: geometrically `d_HH(t) = d_HC(t) + H(t)` where `d_HC` is the first-tail-carbon plane and `H = d_HH − d_HC` is the two headgroup shells (first-tail-C → P, ×2). It uses the **frame-aligned per-frame** `_lipy_rep{r}`/`_dhh_rep{r}` arrays from `core_thickness.npz` (both from the same `traj/` universe, full trajectory), so `H(t)` is genuine per-frame and a within-frame tail↔head trade-off cannot wash out in a mean-of-means. Reports, per (ff, lipid): mean `d_HH`/`d_HC`/`H` with per-frame SD, the **within-run per-frame Pearson `r(d_HC, H)`** (computed per replicate on frame anomalies, then averaged), and a variance partition of the **between-system** `d_HH` spread into core vs headgroup (`Var(d_HH)=Var(d_HC)+Var(H)+2Cov`, cov split evenly) — across all 9, within-lipid across the 3 ff, and FF-averaged across lipids. → `plots/thickness_decomposition.png` (stacked core+headgroup bars, `r` annotated), drawn at the **house 180 × 70 mm** via `figstyle` (`figure_grid` + `categorical_x`, 5 mm legend band, no tight bbox — it would shrink the 180 mm away). The old `suptitle` was dropped: at 9 pt it no longer fits, and it said what a caption should say. **Findings**: the headgroup shell is nearly invariant (**`H` = 1.07–1.15 nm everywhere, SD 0.026 nm**) while the core spans 2.35–2.80 nm, so **~100% of the between-system `d_HH` difference is the hydrophobic core** (77–96% within a single lipid across force fields; ~100% for the DOPC-C18 vs DMPx-C14 tail-length step). The within-run `r(d_HC, H)` is **positive** everywhere (+0.2 to +0.5), i.e. tail and headgroup extensions move *together*, **not** anti-correlated — so no cancelling trade-off was being hidden by the mean. AMBER DMPG's record `d_HH` (3.89 nm) is entirely a **core** effect (2.80 nm core, ordinary 1.10 nm headgroup) — it over-orders the tails, it doesn't extend the PG headgroup.

## Pore radial-density maps for the out-of-equilibrium runs (`pore_density.py` + `plot_pore_density.py`)

A third, independent branch: for the **pore** simulations (a pore driven open by external forces, then a chain-coordinate *rerun*), it builds cylindrically-averaged **(radius, z) density maps** of selected atoms around the pore centre. Same compute→npz→plot split as the other branches.

```bash
# 1. compute (cluster-side, MDAnalysis env) -> data/poredens_{ff}_{lipid}.npz (+ poredens_counts_{ff}_{lipid}.npz)
conda run -n lipid64 python analysis/pore_density.py            # discover all 9
conda run -n lipid64 python analysis/pore_density.py tmp/       # one explicit dir
# 2. plot (anywhere, numpy+matplotlib only) -> plots/poredens_{water,phosphorus,glycerol_c2,midpoint_c}.png
python3 analysis/plot_pore_density.py
python3 analysis/plot_pore_counts.py                            # -> plots/poredens_counts.png
```

- **Discovery mirrors `lipid_properties.py`**: with no positional args it iterates `--forcefields × --lipids` under `--sims-root` (default `~/Simulations`) and looks in `{ff}_{lipid}/{--run-subdir}/` — default `umbrella23` (the pore run is umbrella window 23, one per system, **no replicates**, hence "all 9"). Positional run dirs override discovery (each must hold the `md.{xtc,gro}` + `rerunerr.log` triple), which is how the local `tmp/` test set (from **amber_DMPC**) is run — so only that panel fills in locally; the other 8 render blank. Missing dirs are skipped with a per-system message.
- **Input per run dir**: `md.xtc` + `md.gro` (the **full** water+ion system, *not* the waters-stripped `memb.gro`) and `rerunerr.log`, the chain-coordinate rerun log. The pore centre for each frame is parsed from lines `Cylinder center at (X/Y/Z):  cx cy cz` (nm) via a regex; there is one such line per frame (here 1001 centres ↔ 1001 frames, zipped in file order — the centre barely moves, ~0.2 nm, so any off-by-one is negligible).
- **Four selections**, reusing `make_density_index.detect` + `build_groups` so the per-ff/-lipid water & lipid atom names are handled automatically (the user's reminder — water/lipid names differ per simulation): `water` (reduced to **oxygens** — names `O`/`OW`/`OH2`), `phosphorus`, `glycerol_C2`, `midpoint_C` (mid-chain C, DOPC C9 / DMPx C7, both tails). `terminal_C` etc. from the index are unused here.
- **Binning**: per frame, each atom's in-plane distance `r` from that frame's pore centre (**minimum-image in x/y**) and its **absolute** z go into a 2-D `(z, r)` histogram (fixed edges shared by every run: `r` 0–3 nm, `z` 0–9 nm, both Δ=0.05 nm, so all maps are directly comparable). MDAnalysis positions are Å; centres (nm) are ×10 to match, distances /10 back to nm.
- **Shell-volume normalisation is the point**: raw counts grow with `r` (more area), which would wrongly brighten bulk regions at large r. Counts are divided by the annular shell volume `2π·r·Δr·Δz` (as `π(r_out²−r_in²)·Δz`) and the frame count → a number density in atoms/nm³, so uniformly-filled regions read **flat** across r and the pore feature is what stands out.
- **Colour normalisation is shared across all nine panels** (one scale per atom-type figure, *not* per-panel) — deliberately, so the water-in-pore density can be **compared between force fields** (read down a column: same lipid, the three ff). The shared peak is a **high percentile** (`PEAK_PCTL = 99.5`) of the pooled bins, not the raw max: the innermost radial shells (r→0) have tiny volumes, so dividing counts by them produces a few noise spikes (~2× bulk) that would otherwise grab the whole top of the colour scale and mute the pore contrast. For water the percentile peak ≈ the bulk-water density, so bulk reads ~0.75–0.85 and the pore depletion fills the lower range. The zoom figures use the same shared-percentile scheme but computed **within the CV region** (a separate scale). Small bright specks at r≈0 are the residual tiny-shell noise clipped to 1.0 — expected, not signal.
- **Reading the maps** (validated on amber_DMPC): *water* shows two flat bulk slabs (top/bottom) with a depleted membrane core at large r that **recedes at small r** — water intruding along the pore axis. *phosphorus* shows the two leaflet head-group bands curving **inward** toward the mid-plane at small r — the lipid-lined **toroidal pore** rim. The small-r speckle (r ≲ 0.2 nm) is expected low-count variance in tiny shells, not a bug.
- **Plotting**: `plot_selection(key, stem, title, region=None)` draws a 3×3 grid (lipids across columns, force fields down rows) with `imshow` (viridis, origin lower, `extent` from the edges), radius on x and z-relative-to-pore on y, shared axes, one shared colourbar. Missing `.npz`/selection → blank panel. `aspect="equal"` (1 nm is the same size on both axes, so panels are tall strips, *not* square — intentional; enforced via `set_aspect("equal", adjustable="box")` on **all** axes after setting identical limits, since with `sharex/sharey` only setting it on data panels lets the box get squeezed and 1 nm then differs between x and y). Two figure sets are written:
  - **Full maps** (r 0–3, z ±4.5 nm), all four selections → `poredens_{water,phosphorus,glycerol_c2,midpoint_c}.png`, peak-normalised over the whole map, with a thin dotted **magenta rectangle** outlining the CV cylinder (`CYL_R=0.9`, `CYL_H=2.7` nm → r∈[0,0.9], z∈[−1.35,1.35]).
  - **Zoom maps** restricted to the CV cylinder (`region=(CYL_R, CYL_H/2)`), **water + phosphate only** → `poredens_zoom_{water,phosphorus}.png`, peak-normalised **within the region** (so the zoomed content uses the full colour range) and no rectangle (it *is* the frame).
  Narrow panels drop the edge x-tick under the auto-locator, so ticks are set explicitly (integers 0…3 for the full map; 4 evenly-spaced 0…`r_hi` for the zoom).
- **Per-frame in-cylinder occupancy** — alongside the density maps, `pore_density.py` also writes `data/poredens_counts_{ff}_{lipid}.npz`: the **raw per-frame count** of atoms inside the chain-coordinate CV cylinder for the three `COUNT_SELECTIONS` (`water` oxygens, `phosphorus`, `glycerol_C2`). Counted over **two z-slabs**: the **full** cylinder (`CYL_R=0.9`, `CYL_H=2.7` nm → r≤0.9, |z|≤1.35 relative to that frame's pore centre) and its **middle third** (|z|≤`CYL_H/6`=0.45 nm, the central 9 Å — the pore's narrowest waist). Keys: `frame`, `time_ps` (from the trajectory timestamps), `cyl_r_nm`/`cyl_h_nm`/`cyl_mid_h_nm`, one 1-D count array per selection for the full cylinder, and a `{name}_mid` array for the middle third. Computed inside the same frame loop as the histograms (both masks reuse the per-frame `r`/`z` already needed for binning). `plot_pore_counts.py` (numpy+matplotlib, `palette`) plots these as occupancy-vs-time trajectories in a **3×3 grid with atom type down the rows** (water/phosphate/glycerol C2) and **lipid across the columns** (DOPC/DMPC/DMPG); within each panel the three force fields overlay as lines in the `palette` colours (CHARMM blue / AMBER green / SLipids gold), each row sharing a y-scale. **Each cell is a pair of axes sharing the count (y) axis** (a nested `GridSpecFromSubplotSpec` with `width_ratios=[3,1]`): a ¾-width trajectory and, to its right, a ¼-width **vertical histogram** (`orientation="horizontal"`, `density=True`, `histtype="step"`) that aggregates the trajectory into the marginal count distribution — one outline per force field, with **1-atom (integer) bins** (`edges = arange(-0.5, hi+1.5, 1)`). The trajectory keeps its 200 ns endpoint tick and drops the 0 (`arange(50, tmax+1, 50)`); the histogram's lowest x-tick (`0.00`) is pruned instead (`MaxNLocator(prune="lower")`) so the two can't collide at the shared boundary. Layout is via explicit `GridSpec` margins (nested gridspecs are incompatible with `tight_layout`). Two figures: `plots/poredens_counts.png` (full cylinder) and `plots/poredens_counts_middle.png` (middle third, from the `_mid` keys).

## Lipid tilt modulus with OpenStructure / ost_pymodules (`tilt_convert.py` + `tilt_modulus.py` + `run_tilt.sh` + `plot_tilt_modulus.py`)

A fourth equilibrium-analysis branch: the membrane **lipid tilt modulus** χ per force field / lipid, using the Harries-group `ost_pymodules` code (`~/software/ost_pymodules/lipid_analysis.py`; Khelashvili et al. 2013 JCTC 9:3866, `reference/khelashvili2013calculating*.pdf`). Inputs are the equilibrium runs downloaded to `traj/` as `{ff}_{lipid}.gro` (+ `.tpr`) topology and three replicate `{ff}_{lipid}{1,2,3}.xtc` (9 systems × 3 reps = 27 trajectories, all water-containing).

**Why two stages / two conda envs.** OpenStructure only reads PDB/CRD + **CHARMM DCD**, runs under **Python 2.7**, and has no MDAnalysis. So stage 1 (`tilt_convert.py`, run in `lipid64`) reads `gro`+`xtc` and writes `data/tilt_{ff}_{lipid}_{rep}.{pdb,dcd}`; stage 2 (`tilt_modulus.py`, run with the **OpenStructure python**, `~/miniconda3/envs/openstructure/bin/python`) does the analysis. A full-trajectory multi-model PDB is *not* used — OST loads it only as a list of every frame's entity (memory-punishing); the compact DCD streams frame-by-frame.

**OST build specifics (this machine).** The `ost` here was compiled **with** the image (IPLT) libraries — required, since the membrane normal comes from a water/lipid **density** interface (`img.CreateImage`, `EntityToDensityRosetta`); without img the method cannot run. Two things a plain python (vs the interactive `ost` launcher) must set up, both handled in `tilt_modulus.py`: (1) `import ost.img` so `ost_pymodules`' `from ost import *` resolves `img.*`; (2) `SetPrefixPath` to OST's install root (`$DNG_ROOT`/`$OST_ROOT`, else walk up from `ost.__file__` to the dir holding `share/openstructure`) so `EntityToDensityRosetta` finds `atom_scattering_properties.txt` (else "missing PrefixPath").

**`tilt_convert.py` preprocessing** (all force-field-specific fixups so `AnalyzeLipidTiltAndSplay` sees each lipid as ONE residue with a head→tail vector inside it):
- **Heavy atoms only** (drop `name H*`) for lipids *and* water, applied to all three force fields for a consistent density and because it removes the AMBER hydrogen-name collisions below. The interface density and the tilt director are heavy-atom quantities, so this is a negligible, deliberate deviation from the all-atom paper.
- **AMBER residue merge.** Lipid17 splits each lipid into three residues (tail `OL`/`MY`, head `PC`/`PGR`, tail `OL`/`MY`) that share a resid and sit contiguously. They get one resname (`LIP`) + a shared resid so OST reads them as one residue. Both tails otherwise carry identical carbon names (`C1{n}`) which OST silently **merges** (duplicate atom names in one residue → the 2nd tail's atoms vanish); the fix renames the **second** tail's carbons `C1{n}` → `CB{n}` (kept starting with C so the element still reads carbon). CHARMM/SLipids are already one residue per lipid with distinct sn-1 `C2x` / sn-2 `C3x` names.
- **AMBER water is one giant residue.** The AMBER gro numbers *every* water with the same resid (Lipid17/GROMACS quirk) → MDAnalysis sees one water residue, and OST collapses all the identically named oxygens into a single atom. `tilt_convert` rebuilds water as **one residue per oxygen** (a fresh `Universe.empty`, resids stacked above the lipids) via `mda.Merge(lipids, wu.atoms)`. Harmless for CHARMM/SLipids (already per-molecule). Ions dropped. (Do **not** use `mda.Merge` on the raw water — that was the original bug that lumped all 17k waters into resid 128.)
- Bilayer is assumed already whole & centred in z (cluster trjconv output); no re-centring. The per-frame box **is** written into the DCD (`merged.dimensions = u.dimensions`) — the no-tile analysis runs `PBC=False` and ignores it, but the PBC-tiling cross-check below needs the cell vectors.

**Method (matches Khelashvili 2013, verified against paper + SI + `lipid_analysis.py`):** the lipid **director** t = geometric midpoint of the phosphate P and the backbone glycerol **C2** → COM of the **last three carbons of each chain** (six atoms; SI Fig. S2). Tilt θ = angle(t, membrane normal). χ from the PMF fit `−k_BT ln[P(θ)/sin θ] = (χ/2)θ²`, χ = 2×curvature (`FitTiltDistribution`). **χ is per-lipid in k_BT/rad², with NO area normalisation** — `ExtractTiltAndSplayModuli` uses `lipid_area` only for the *splay/bending* modulus. `tilt_modulus.selections()` gives, per lipid: head `aname=P,C2` (AMBER `P31,C2`; the library's mass-weighted COM differs from the true geometric midpoint by <1 Å, negligible over the ~18 Å director), tail = last-3 carbons of each chain (`C2x,C3x` for CHARMM/SLipids; `C1x,CBx` for the renamed AMBER tails), with `TERM` = 18 (DOPC) / 14 (DMPx).

**Normal source & a sampling gotcha.** The paper uses the *global* bilayer z for its flat patches; `ost_pymodules` uses the *local* water-density interface normal (the general formulation). For these flat 128-lipid / 64 Å patches they converge. But the local normal is only clean if the interface is well sampled: a coarse trajectory stride undersamples the density → noisy normals → inflated tilt → **suppressed** χ (stride-20 gave ~11; full frames give ~14, matching a global-z cross-check of ~13.6). Run production at `--stride 1` (`--density-stride 10` is enough for the average interface); `within_size_normals=10` on the *smoothed* density surface is fine (unlike raw phosphate points, which need ≥15).

**PBC unit-cell tiling is NOT needed here (validated).** The library's example replicates the unit cell to its neighbours (and computes tilts only for the central cell) "to avoid boundary effects on the interfaces and hence on the normal vectors" — because its system is a *curved hexagonal phase*. For a flat bilayer the director is intramolecular and the normal is ≈z everywhere, so a single-cell (non-tiled) interface gives the same normals. Directly checked with the example's exact procedure (`ExtendTrajectoryToNeighboringUnitCells` 2×2 in-plane → `WrapTrajectoryInPeriodicCell` around the central cell → `do_tilt` bool prop on central-cell lipids only): CHARMM DMPC χ = 14.03 (no tile) vs 14.10 (tiled) — a 0.5 % shift, within replicate scatter. So the pipeline runs **without** tiling; the box is still carried in the DCD so tiling can be switched on. `tilt_tiled_validate.py` (kept in the job scratch, not committed) is the cross-check script.

**Splay is skipped.** `tilt_modulus.analyze()` calls the library's tilt pieces directly (`GetBoundaryBetweenViews` → `AssignNormalsToLipids` → `AnalyzeLipidTilts` → `FitTiltDistribution`), not the `AnalyzeLipidTiltAndSplay` wrapper, because we only need tilt and the wrapper's splay step has a bug (`AnalyzeLipidSplays` calls `GetBoolProp('')` with no guard, and needs per-cell chain names) irrelevant here. The library source is left unmodified.

**Within-run χ error (block averaging).** `tilt_modulus.py` also keeps the raw per-frame per-lipid tilt array and, from it, the per-frame tilt **moments** `⟨θ⟩(t)` and the χ-relevant **spread** `⟨δθ²⟩(t)`. It sizes a block average from the decorrelation time `g_var` of `⟨δθ²⟩(t)` (via `autocorr` — pymbar is unavailable in the OST py2.7), **refits χ per block with the same `FitTiltDistribution`**, and reports `chi_block_sem` (the autocorrelation-aware within-run SEM, typically ~3× the pooled-fit bootstrap `dchi`). The block mean reproduces the pooled χ (no bias). Raw tilts + moments + block meta are saved to `data/tilt_series_{ff}_{lipid}_{rep}.npz` **so a re-block never needs the expensive OST pass again**. `g_var` is also read by `run_lipidator_blocks.py` (below).

**χ is fitted on the pymbar production span `[t0:]`** (`analysis/refit_tilt_t0.py`), the same convention as APL/d_HH/d_HC. The refit is cheap — the raw per-frame per-lipid `tilts` array is already in `tilt_series_*.npz`, so it needs only `FitTiltDistribution`, **not** another OST density/normal pass — but it still runs under the OpenStructure Python 2.7 (`lipid_analysis` does `from ost import *` at import): `~/miniconda3/envs/openstructure/bin/python analysis/refit_tilt_t0.py`. `t0` is the **`tilt` observable** in `equilibrium_timeseries_stats.json` (the `⟨δθ²⟩(t)` spread — so **run `stats.py` first**); the script slices `tilts[:, t0:]`, refits the pooled χ, re-derives `g_var`/blocks/`chi_block_sem` on the production span, and rewrites `tilt_moduli.json` **in place**: the canonical keys (`chi_kT`/`dchi_kT`/`chi_block_sem`/`g_var_frames`/`n_blocks`/`block_size`/`n_frames`) become the post-t0 values, the previous whole-run ones are preserved once as `*_full`, and `t0_frames`/`t0_ns` record what was dropped. Always refitting from the raw npz makes it **idempotent**. Effect: negligible for the well-behaved systems (t0 ≈ 0–30 ns, Δχ < 0.05) and material only where pymbar finds a long burn-in — **SLipids DMPG rep 1 14.59 → 16.03** (t0 = 370 ns), rep 3 14.61 → 14.99, AMBER DMPG rep 3 20.88 → 21.41. Because χ's own `t0` is generally *much* shorter than APL's or d_HC's (tilt decorrelates in g ≈ 7–17 frames), the tilt burn-in is mild even for the DMPGs. Run it after every `run_tilt.sh` pass, and **before** `run_lipidator_blocks.py`, which reads the (now post-t0) `g_var` for its block sizing.

**Running it.** `run_tilt.sh` loops `{ff}×{lipid}×{rep}`: convert → compute χ (+ block SEM, appended to `data/tilt_moduli.json`, keyed `{ff}_{lipid}_{rep}`, with `chi_kT`/`chi_block_sem`/`n_blocks`/`g_var_frames`) → delete the bulky DCD (keep the small `.pdb`). Resumable; `FRESH=1` starts the json clean; `FFS`/`LIPIDS`/`REPS`/`STRIDE`/`DENS_STRIDE` env vars subset it. `plot_tilt_modulus.py` (numpy+matplotlib+`autocorr`) aggregates to `data/tilt_moduli_summary.json` and a grouped bar chart `plots/tilt_modulus.png` — lipids on x, force fields as `palette` colours, error bars = **hierarchical 95% CI** (`hierarchical_ci_from_estimates`: per-rep χ + `chi_block_sem`, combined with the replicate spread). The tilt angle is in **radians** and χ natively in **k_BT/rad²**; since χ is an energy per rad², the chart's **primary (left) axis is kJ/mol/rad²** = χ·RT at **T = 310 K** (RT = 2.577 kJ/mol), with the k_BT/rad² scale kept on the right-hand twin axis. Both units + the 95% CI are stored per system in the summary json (`chi_kT`/`chi_kJ_per_mol`/`ci95_kT`/`ci95_kJ_per_mol`; `sd_*` kept too). Sanity ranges: DMPC ≈ 14, DOPC lower (unsaturated, softer) ≈ 11, CHARMM/SLipids DMPG ≈ 13–15 — all in the literature ~10–15 k_BT/rad². **AMBER DMPG is a genuine outlier at χ ≈ 20–22** (reproducible across all 3 reps; confirmed real, not an edge artifact, by the tiled cross-check 21.3→21.9) — a real force-field effect (anionic PG + Na⁺), not a bug.

## Lipid tilt modulus, second method: Lipidator toolkit (`make_director.py` + `make_lipidator_index.py`)

An independent cross-check of the tilt modulus using the **Lipidator toolkit** (Allolio/Harries, `~/software/lipidator-toolkit`; ReSiS method, `resis` binary). Unlike `ost_pymodules` it reads GROMACS **xtc natively** (`resis traj.xtc library.ldx index.ndx [wtc]`) and reports the tilt modulus **area-normalised in kt/nm²** (not the per-lipid k_BT/rad² of `ost_pymodules`; the two relate as κ[k_BT/nm²] = χ[k_BT/rad²]/A_lipid, which agrees to ~10 % — a mutual validation).

The tool reads **only the xtc** (coordinates + atom count — no names/residues), so the topology is defined entirely by two files, and **AMBER's 3-residues-per-lipid layout is irrelevant** to it:
- **Index (`data/lipidator_{ff}_{lipid}.ndx`, `make_lipidator_index.py`)**: one GROMACS group `[ LIPID ]` (name must match the director) listing the **1-based global index of each lipid's first atom**. Single-residue ff → the residue's first atom; AMBER → first atom of each contiguous residue-triple (tail-head-tail).
- **Director (`.ldx`, `make_director.py`)**: per-lipid `[P/head][1]`, `[CHAIN1/tail][2]`, `[C2/surface][3]`; entries are `(position, mass)` with **position 1-based within the lipid counted from its first atom** and mass an element letter (→ isotope mass) or a float. The tool computes atom = (position−1)+(ndx−1); director = COM(head)→COM(tail). Recipe (matched to the shipped CHARMM lib, verified to reproduce its DMPC/DOPC offsets exactly): head = phosphate + glycerol C2 + both carbonyls + first two acyl carbons of each chain; tail = last three acyl carbons of each chain; surface = head (element mass) + tail (weight 5.0). Force-field atom names: CHARMM/SLipids `P`,`C2`,`C21`/`C31`,`C2x`/`C3x`; AMBER `P31`,`C2`,`C11`/`C21`,`C1x` (per tail residue). **Leave two blank lines after each lipid block.**
- The shipped libraries were incomplete for our lipids: `charmm.ldx` had DMPC/DOPC but **not DMPG**; `slipids.ldx` had only POPC/BMP/POPG. `make_director.py` appends the missing entries (CHARMM DMPG; SLipids DMPC/DOPC/DMPG) and writes `amber.ldx` (DMPC/DOPC/DMPG); idempotent, and `--check-charmm` re-verifies the recipe against the shipped CHARMM offsets. SLipids DOPC needs its own offsets (its atom order differs from CHARMM; DMPC/DMPG orders are identical).
- **Running it:** `run_lipidator.py` (stdlib only) runs `resis` over all 9 systems × 3 reps, parses the `Bilayer Tilt: kappa … kt/nm²` (and APL) from stdout, and writes `data/lipidator_moduli.json` (per-rep) + `data/lipidator_moduli_summary.json`. **Within-run κ error** (`run_lipidator_blocks.py`, `lipid64` + `PYTHONNOUSERSITE=1`): `resis` has no frame-range flag, so the block analogue is to **run it on contiguous sub-trajectory xtc slices** (written via MDAnalysis). Block size is taken from the OST-side `g_var` in `tilt_moduli.json` (same bilayer ⇒ same tilt decorrelation time — so **run the tilt pipeline, and `refit_tilt_t0.py`, first**); writes `data/lipidator_blocks.json` (per-rep `kappa_full`/`kappa_block_sem`/`n_blocks`). **κ is also measured on the production span `[t0:]`**, matching χ and the per-frame observables: `resis` has no frame-range flag, so the frames before `t0` are simply dropped when the sub-trajectory xtc is written — the reported `kappa_full` *is* the production-span value (with `t0_frames`/`t0_ns` recorded and the old whole-run number kept as `kappa_whole_run`); `--no-t0` restores the whole-run behaviour. `t0` is the same `tilt` observable from `equilibrium_timeseries_stats.json` that sizes the blocks. `plot_lipidator.py` (numpy+matplotlib+`autocorr`, `palette`) → grouped bar chart `plots/lipidator_tilt_modulus.png` with error bars = **hierarchical 95% CI** (from `lipidator_blocks.json` when present — per-rep κ + block SEM + replicate spread; falls back to SD-only from `lipidator_moduli.json`); it also **regenerates the summary json** (`tilt_kt_per_nm2`/`tilt_kJ_per_mol_nm2`/`ci95_*`, conversion ×RT at 310 K). The chart's **primary (left) axis is kJ/mol/nm²** (= κ·RT at T = 310 K), with the native k_BT/nm² scale kept on the right-hand twin axis.
- **Results** (κ_θ, kt/nm², production span, mean ± hierarchical 95% CI): CHARMM 14.7/21.2/19.3, AMBER 15.3/22.4/52.3, SLipids 13.9/21.2/30.3 for DOPC/DMPC/DMPG — tracking the `ost_pymodules` per-lipid results after ÷area (DOPC softest, AMBER DMPG stiffest).
- **Duplicate-block gotcha:** `LoadIndices` iterates *every* director entry and matches each against the index group, so a **duplicated `#LIPID` block in a `.ldx` double-counts that lipid** (n_lipids doubles → APL halves → the area-normalised κ doubles, silently). A merge had left two identical `#DMPC` blocks in `charmm.ldx` (→ CHARMM DMPC read 42 instead of 21); de-duplicated. Keep exactly one block per lipid per library.
- **CHARMM DMPG segfault (fixed):** `resis` crashed (EXC_BAD_ACCESS at `instafit.cpp:416`, `c->size()` with `c=GetCenters()==NULL`). Root cause was a one-character typo in the shipped `charmm.ldx`: the DMPIP2 block's group header was `" [C2][3]"` with a **leading space**, which makes `ReadTopology`'s `[]`-tokenizer read the group id as `"C2"` (not the digit `3`) → `READ_FAIL`; `LoadLibrary` then `break`s at the first failed block, so **every lipid after DMPIP2 (incl. the appended DMPG) never loads** → the `[ DMPG ]` index matches nothing → `centers` empty → `GetCenters()` NULL → null deref. Removing the leading space fixes it (CHARMM DMPG = 19.4 kt/nm²); CHARMM DMPC/DOPC were unaffected because they precede DMPIP2. Lesson: keep director group headers flush-left, no leading whitespace.
- **Build note:** the toolkit no longer compiles as-shipped on current Apple clang (21.x) — `trjflib/minimath.hpp` illegally does `namespace std { struct tuple {...} }`, which now clashes with the real `std::tuple` pulled in via `<string>` ("reference to 'tuple' is ambiguous"). The `2112d9e` "shims" commit on the toolkit's master fixes this; build with `cmake -S . -B build && make -C build` (CommandLineTools `c++`, Eigen/Boost from conda base). The pre-existing `resis` binary already works, so a rebuild is only needed if recompiling.

## Conventions that span multiple files

- **`analysis/lipiddefs.py` is the single source of truth for the systems and the force-field vocabulary** — don't re-declare any of it in a script. It holds `FORCEFIELDS`/`FF_LABELS`/`FF_LABELLED`/`LIPIDS`/`REPS`, the residue-layout map `SCHEME` (`charmm`/`slipids` → `"single"`, `amber` → `"amber"` — nearly every ff conditional in the repo is really this test), `TAIL_NC` (alias `TERM`), `DOUBLE_BOND` + `CHAIN_MID`, `AMBER_HEAD`/`AMBER_TAIL`, `PHOSPHATE_NAMES`/`PHOSPHATE_SEL` (`"name P P31"`), the solvent/ion resnames (`WATER`, `WATER_NAME`, `WATER_OXYGEN`, `SODIUM`, `MAGNESIUM`, `CALCIUM`), and the helpers `lipid_resnames`/`chain_atom_names`/`midpoint_carbon`/`n_unsat`. It is **pure stdlib and Python 2/3 compatible** (like `autocorr.py`) because `tilt_modulus.py` imports it under the OpenStructure Python 2.7 — no f-strings, no pathlib, set literals written as `set([...])`. `palette.FORCEFIELDS` is now *derived* (`[(ff, label, palette.COLORS[ff]) for ff, label in lipiddefs.FF_LABELLED]`), so the ff keys/labels exist in exactly one place and only the hexes live in `palette.py`. `make_density_index.py` re-exports `TAIL_NC`/`AMBER_HEAD`/`AMBER_TAIL`/`chain_atom_names` (several scripts import them from there, and `mdi.` is the established idiom), and `make_order_index.py` re-exports `TAIL_NC`; both re-exports are thin aliases of the lipiddefs values, not copies. `lipid_properties.py` imports the names it historically used under aliases (`REPS as REPLICATES`, `PHOSPHATE_SEL as PHOSPHATE`, `AMBER_TAIL as AMBER_TAIL_RESN`).
- **Two user-facing READMEs.** The root **`README.md`** covers the **simulation-setup** stage (`setup_scripts/` + `setup_files/`: system build, `pull.ndx`/CV groups, the `SLICE_COORD_*` chain-coordinate settings, equilibrium replicates, steered pull, umbrella-window selection, the ξ=1 window + `close` replicates, WHAM, the MDP/force-field matrix) and links to the analysis guide at the end. **`analysis/README.md`** is the analysis reproduction guide (canonical run order, the two-copy trajectory layout, how to adapt to new ff/lipids, output artifacts); its commands are written to be run **from the repository root** even though the file lives in `analysis/`. This CLAUDE.md is the dev-notes companion to both; keep the three consistent.
- **Two copies of every equilibrium trajectory** (an env split, not sloppiness): both are produced on the cluster from one `md.xtc` by a single `-pbc mol -center` `trjconv` pass (centering on the `MEMB` group from `pull.ndx`), differing only in output selection. **Copy A** `~/Simulations/{ff}_{lipid}/eq{i}/{memb.gro,inbox.xtc}` = **lipid-only** (waters+ions stripped), for cluster-side lipyphilic (`lipid_properties.py`) + g_lomepro. **Copy B** `traj/{ff}_{lipid}{i}.xtc` + shared `traj/{ff}_{lipid}.gro` (one rep's downloaded `md.gro`) = **full system** (water needed for OST's density interface), for the local OpenStructure / Lipidator / core-thickness / density-index tools. `traj/` is the single canonical home for the full-system trajectories *and* topologies (the old `tmp/*.gro` copy is retired). MDAnalysis can't read the GROMACS 2026 `.tpr`, so the local tools use the `.gro` as topology.
- **Force-field color scheme is fixed everywhere and centralized in `analysis/palette.py`** (imported by all the plotting scripts — don't hard-code hexes): a colour-blind-friendly blue/gold/green set — CHARMM = blue `#2171b5`, AMBER = gold `#d4a017` (AMBER is amber), SLipids = green `#0f7d3b`. Each also has a matching light→dark sequential colormap (`palette.CMAPS`) for the 10-replicate `close_pullx` gradients; AMBER's gold ramp deliberately stops short of white so light replicates stay visible. The trio was checked with the dataviz colour-blindness validator (worst adjacent CVD ΔE 16.9) — re-validate if you change it, since a brighter yellow collapses onto green under red/green CVD. (AMBER↔SLipids were swapped gold↔green so AMBER reads as amber; the three hexes are unchanged, so the CVD separation still holds. The old black/red/green was an xmgrace-compatibility artifact, now retired.)
- **Data-file naming is load-bearing** — the scripts parse it, there is no manifest. `ff` ∈ {`charmm`, `amber`, `slipids`}, `lipid` ∈ {`DOPC`, `DMPC`, `DMPG`}:
  - `{ff}_{lipid}_close{1..10}_pullx.xvg` — 10 "close" (pore-closing) replicates.
  - `{ff}_{lipid}_profile.xvg` — full 100 ns PMF; `{ff}_{lipid}_part{1..5}_profile.xvg` — five consecutive 20 ns windows; `{ff}_{lipid}_20-100_profile.xvg` — an 80 ns window.
  - `plot_range_vs_time.py` reads the sampling window straight from the `gmx wham` `-b`/`-e` flags embedded in each profile's `.xvg` header comments.
- **`.xvg` parsing**: every script has its own tiny loader that skips lines beginning with `#`, `@`, or `&` (comment/xmgrace-metadata) and takes columns 0 and 1.

## Visualization (`analysis/render_snapshots.py` + `analysis/cylinder_pml.sh`)

**`render_snapshots.py` is the end-to-end renderer** for the 18 snapshot panels the figures use (`snapshots/{ff}_{lipid}_{last,close}.png`, 1358 × 1358 px = 57.5 mm at 600 dpi, transparent ground — the size `make_figures.py` places at native scale). It generates the whole `.pml` from Python — load, style, camera, `png`, `quit` — and runs `pymol -cq` on it, the same pattern as `make_box_snapshots.py`; `--ff/--lipid/--set` subset it, `--dry-run` writes only the `.pml` (`snapshots/{ff}_{lipid}_{set}_render.pml`, a generated artifact). Inputs are `{ff}_{lipid}_last_conf.gro` (end-of-umbrella pore, cylinder drawn) and `{ff}_{lipid}_close.gro` (closed pore, `zoom` on the lipid with fog off), preferring a `*_renumbered.gro` where one exists (raw Lipid17 gros number every residue 1, which PyMOL reads as one giant residue). **This replaced a hand-driven workflow**: the committed `snapshots/*_{cyl,close}_style.pml` carry styling only — no `load`, no `png`/`ray` — so they were `@`-sourced onto an already-loaded structure and rayed by hand, and the throwaway drivers that did it were never committed. Those files are now **inputs, not recipes**: the `cyl` line is read back out of `{ff}_{lipid}_cyl_style.pml`, which stays the only local record of the cylinder geometry (it comes from the run's `slurm.*.err`). `cyl` itself is the `~/.pymol/draw_cylinder.py` plugin loaded from `.pymolrc`, so PyMOL must **not** be run with `-k`; it `load_cgo`s a new object, and PyMOL's auto-zoom onto that small cylinder *is* what frames the `last` panels (there is no explicit zoom). **Both framings then need their clipping planes widened**: auto-zoom sets a slab ~2× the cylinder (54 Å against a ~71 Å-deep box) and `zoom` fits the lipid selection, so either way the foreground spheres are sliced open — the visible artifact in the pre-`render_snapshots.py` panels. The script resets near/far to `d ∓ span` (camera distance ∓ the system's own extent) after the framing command, which touches neither the scale nor the centring and hides nothing: with the tails already off, the foreground is the same headgroup surface either way (checked against an atom-selection depth slab, which renders identically). Panel style: lipids as **spheres, `gray30`**, phosphorus **orange**, tails hidden, water/ions as spheres with **all hydrogens hidden** (so water reads as bare oxygen spheres) and the ions explicitly coloured; default sphere scale. Re-run `make_figures.py`, `figures/fig02_pore_energy.py` and `figures/fig04_pore_occupancy.py` after a re-render.

`cylinder_pml.sh`:

Run from a run directory; reads the cylinder geometry out of the newest `slurm.*.err` and writes `cyl_style.pml` for PyMOL. Example configurations for every ff/lipid pair live in `snapshots/*_example.gro` — use them to check residue/atom names.

Force field and lipid come from the `ff_lipid` directory name, but on the cluster the run directory is nested several levels below it (umbrella windows, close replicates), so the script **walks up the path** to find it rather than reading the parent — stopping at a directory named `Simulations`, above which it won't look. Both halves must parse as a known force field *and* lipid, so intermediate dirs that merely contain an underscore (`run_2`, `window_5`) are not mistaken for it. `cylinder_pml.sh <ff> <lipid>` overrides detection entirely.

**The residue-name matrix each force field needs** (all verified against `snapshots/`):

| | water | ions | lipid residue(s) |
|---|---|---|---|
| CHARMM | `TIP3` | `SOD` `CLA` `MG` `CAL` | one residue: `DOPC`/`DMPC`/`DMPG` |
| AMBER | `TP3` | `Na+` `Cl-` `MG` `CA` | head `PC` (DMPG: `PGR`) + tail `OL` (DOPC) / `MY` (DMPC, DMPG) |
| SLipids | `SOL` | `NA` `CL` `MG` `CA` | one residue: `DOPC`/`DMPC`/`DMPG` |

- **Hiding tails** is the one genuinely force-field-dependent step. AMBER splits each lipid into head and tail residues, so it's just `resn OL`/`resn MY`. CHARMM/SLipids put the whole lipid in one residue, so the tails are selected by atom name: `name C2*+C3* and not name C2+C3+C21+C31` — the exclusion matters, because glycerol `C2`/`C3` and ester carbonyls `C21`/`C31` match the wildcard but live in AMBER's *head* residue. Hydrogens used to be added by bond (`hydro and neighbor ...`), since CHARMM tail-H names (`H2R`,`H2X`,…) collide with glycerol `HS`/`HX`/`HY`; `render_snapshots.py` no longer needs that, as it hides every hydrogen anyway. Verified in PyMOL: this hides exactly the same atom counts as AMBER's residue selection (DOPC 12800, DMPC/DMPG 10240) and leaves the same heads visible (4864/4864/3968).
- **PyMOL gotchas**: `+`/`-` in AMBER's `Na+`/`Cl-` are selection-list characters and must be backslash-escaped (`resn Na\+`) — quoting does *not* work for `+`. `elem` selections are useless here: PyMOL assigns no elements when loading a `.gro`.

## Simulation setup details (`setup_scripts/`, `setup_files/`)

## Equilibrium summary table for the manuscript (`make_equilibrium_table.py`)

`analysis/make_equilibrium_table.py` (numpy + stdlib) parses every **equilibrium**-derived observable in `data/` and emits a drop-in LaTeX table `data/equilibrium_summary_table.tex` (needs `\usepackage{booktabs,multirow,amsmath}`), one row per `(lipid, force field)`. The pore branches (PMFs, cylindrical pore densities, closure trajectories) are excluded — not equilibrium quantities. Grouped columns:

- **lipyphilic** (from `lipprops_*.npz` + `core_thickness.npz`): APL (Å²), P–P thickness `d_HH` (nm, ÷10 from the Å npz), hydrophobic-core thickness `d_HC` (nm, the first-tail-carbon `MembThickness` metric from `core_thickness.npz`, key `{ff}_{lipid}_lipy_rep{n}` — see the d_HC section; agrees with the tail-density-width metric to ~0.02 nm), and lateral diffusion `D` (**µm²/s**, ×10⁸ from the cm²/s `_D` key). `core_thickness.npz` is an optional input — d_HC is blank/flagged if absent. (The lipyphilic `⟨S_CC⟩` column was **dropped** — its per-carbon profile is a per-bond-parity artifact, see the S_CC note in the lipid-properties section; the g_lomepro `⟨−S_CD⟩` column is the order parameter kept.)
- **g_lomepro**: chain-averaged `⟨−S_CD⟩` (mean of col 2 of the `_scd_sn{1,2}.dat` files, both tails pooled).
- **tilt modulus**: `χ` (ost_pymodules, kJ/mol/rad², per-rep `tilt_moduli.json`) and `κ_θ` (Lipidator/ReSiS, kJ/mol/nm², per-rep `lipidator_blocks.json`) — read per replicate (value + block SEM) for the hierarchical CI, not from the mean/SD summary JSONs.

Every cell is **mean ± hierarchical 95% CI** (see the autocorrelation section below), *except* `D` and `⟨−S_CD⟩` which keep **± SD across the 3 replicates** (fitted scalar / profile per run, no within-run series). The point estimate is unchanged from the old convention (grand mean over frames & reps); only the error changed. Sources are now the **per-replicate** JSONs, not the summaries: APL/d_HH from `lipprops_*.npz`, d_HC from `core_thickness.npz`, each sliced to its pymbar production span `[t0:]` (t0 read from `equilibrium_timeseries_stats.json`, so **run `stats.py` first**); χ from `tilt_moduli.json` (`chi_kT` + `chi_block_sem`), κ from `lipidator_blocks.json` (`kappa_full` + `kappa_block_sem`), both × RT(310 K)=2.577 → kJ/mol. `collect()` (reused by the vs-barrier plots) returns `(mean, err)` where `err` is the CI half-width for the hierarchical columns, SD for `D`/`⟨−S_CD⟩`. The group headers carry `\cite{}` keys for each toolkit (under a "Software" spanner, plus `\cite{chodera2016simple}` in the caption) and each lipid gets an extra **`Exp` row** of hardcoded experimental reference values + citations (APL/`d_HH`/`D`, in the `EXPERIMENTAL` dict; other columns blank), so the table needs a bibliography with those keys. Missing systems are reported at the end (flagged as "likely not pulled from the cluster"). **Design notes / flags:** there is **no "pure MDA" column** — every MDAnalysis-based equilibrium observable also goes through lipyphilic (or its leaflet assignment), and tilt-convert's MDA use just feeds OpenStructure; the order-parameter column (`⟨−S_CD⟩`) is a **chain-averaged scalar** (lossy — the full per-carbon profile lives in `plots/lipprop_scd.png`); the lipyphilic `⟨S_CC⟩` column was **removed** (per-bond-parity artifact — see the S_CC note above); **registration is deliberately excluded** (it measures domain registration in phase-separating mixtures, so it is near-zero and uninformative for these single-component bilayers); the equilibrium **`gmx density` profiles** are equilibrium data but z-distributions with no replicates, so they are not table-able scalars.

## Autocorrelation diagnostics for the equilibrium timeseries (`stats.py`)

`analysis/stats.py` computes, per force field / lipid / replicate, the equilibration cutoff **`t0`**, the **statistical inefficiency** `g` (in frames) and the max effective number of uncorrelated samples **`Neff_max`** for each per-frame equilibrium observable. **`t0` comes from pymbar** (`detect_equilibration`, `t0 = argmax Neff`, Chodera 2016 — `reference/chodera2016simple.pdf`); **`g` comes from `autocorr.py`** (the shared pure-numpy engine, validated bit-identical to pymbar's `statistical_inefficiency(fft=True)` — see the autocorrelation section). pymbar lives in the **base** conda env (FFT path needs `statsmodels`), so run it there: `conda run -n base python analysis/stats.py`.

- **Importable**: `analyze_series(A)` returns `{t0, g_full, g_prod, Neff_max, mean_prod, sd_prod, sem_within, N}` for one series — table/plot scripts call it (or read the JSON it writes) instead of a separate run. The reported `g` is **`g_prod`** (statistical inefficiency of the *production* span `[t0:]`, per Chodera — not the transient-inflated whole-series `g_full`, which is kept per-rep as a diagnostic).
- **Observables** (per-frame series): `apl` (area/lipid, mean over lipids per frame), `thickness` (d_HH), `dhc` (d_HC, from `core_thickness.npz` key `{ff}_{lipid}_lipy_rep{n}` — an *optional* input, so absent → no d_HC stats), `tilt` (the per-frame lipid-tilt spread ⟨δθ²⟩ from the OST pipeline's `data/tilt_series_{ff}_{lipid}_{rep}.npz` key `theta_var` — the quantity χ is fitted from, so the tilt modulus gets an equilibration row too; also optional), `registration`, and `scc` (chain-averaged S_CC per frame — the order-parameter array is stacked `[tail, frame, chain]`, so `reshape(2, F, m, n_carbons).mean(axis=(0,2,3))`; `F` from the APL frame count). `lateral_diffusion` is **excluded** (D is one fitted scalar; MSD is nonstationary).
- Prints a per-observable `g_prod`/`Neff_max` table (mean ± SD over the 3 reps, plus `min Neff_max`) **and a within-run vs between-run variance decomposition** (`decompose()`), then writes both (`per_replicate` incl. `t0` + `decomposition`) to `data/equilibrium_timeseries_stats.json`. **This JSON is the `t0` source of truth** the tables and the `lipprop_traj_*` plots read to drop the burn-in.
- **`Neff_max` findings** (on the full **500 ns** = 2501-frame runs): each run holds tens–hundreds of independent samples (`Neff_max` ≈ 50–100 for well-behaved APL/thickness/d_HC; registration ≈ 100–700). **AMBER DMPG is the least-sampled everywhere**: pymbar detects a huge burn-in (t0 ≈ 380–480 ns for APL/S_CC/d_HC — it discards **78–86 %** of the trajectory, from the slow acyl-chain ordering visible in `lipprop_traj_memb_thickness.png`), leaving `Neff_max` ≈ 20–26. SLipids DMPG similar (t0 ≈ 320–390 ns). **Policy: trust pymbar's per-rep `t0`** (it correctly leaves well-behaved systems at t0≈0) even though for the DMPGs the per-rep t0 disagrees by 300+ ns (Chodera's own caveat: unreliable when the run isn't ≫ the slow autocorrelation time) — the resulting CI is between-run-dominated there anyway, so robust to the exact t0.
- **Variance decomposition** — per system, each run's mean carries a within-run sampling error `SEM_r = SD_frame/√Neff_max` (variance of a correlated series' mean, computed on the post-`t0` equilibrated region). Across the 3 reps it compares `between_sd` (sample SD of the per-run means — the replicate spread) with `within_sem` (RMS of the per-run SEMs — the scatter expected from sampling noise alone). Their **ratio** is the verdict: `<1.5` **poolable** (replicate scatter IS just sampling noise → pooling to ~`3·Neff` effective samples is defensible, hugely more power); `1.5–3` borderline; `≥3` **between-run** (genuine run-to-run variance → keep n=3). Also reports `sigma_between = √max(0, between_sd² − within_sem²)` (variance-components estimate of the true run-to-run SD) and the `~pooled n`. Heuristic thresholds, and the ratio is itself noisy at n=3.
- **Decomposition findings** (500 ns data): most CHARMM/SLipids PC systems are **poolable** for APL/thickness/d_HC/S_CC (ratio <1.5, `~pooled n` ~150–500). **The DMPGs are the hard cases**: AMBER DMPG is `between-run` for thickness (3.2), S_CC (8.5) and d_HC (4.7), borderline for APL/registration; SLipids DMPG is `between-run` for APL (4.0)/thickness (3.0). AMBER DOPC is borderline for APL/thickness/S_CC. Where between-run, the replicate spread is real irreproducibility and the hierarchical CI's `max(between², within²)` term is the between-run value — n=3 must stand. This decomposition (`decompose()`) is the *diagnostic* justification for the hierarchical-CI regime switch used in the tables/plots. Heuristic thresholds; the ratio is itself noisy at n=3.

## Autocorrelation-aware error bars & the hierarchical CI (`autocorr.py`)

`analysis/autocorr.py` is a **dependency-light (pure numpy), Python 2- and 3-compatible** engine shared by `stats.py` (py3/base) and `tilt_modulus.py` (**OpenStructure py2.7, where pymbar is unavailable** — this is *why* it exists as a standalone numpy module rather than living in `stats.py`). Its `statistical_inefficiency` reproduces `pymbar.timeseries.statistical_inefficiency(fft=True)` **bit-identically** on the project series (validated), so it is the single `g` source everywhere; pymbar is retained only for `detect_equilibration` (the `t0` scan). Contents:

- `statistical_inefficiency(A)` → `g = 1 + 2τ_ac` (initial-positive-sequence truncation); `neff(A)` = N/g.
- `choose_n_blocks(n_frames, g)` / `block_ranges` / `block_sem` — block-averaging helpers (blocks sized ≥ g so block estimates are ~independent).
- `t95(dof)` — hardcoded two-sided 95% Student-t table (no scipy), → 1.96 asymptotically.
- **`hierarchical_ci(series, t0s=None)`** — the CI for **per-frame** observables. Takes a list of per-rep 1-D series; optional `t0s` (pymbar cutoffs) restrict each to its production span `[t0:]` **before** the mean and `g` are estimated (Chodera: `g`/σ² are production-span quantities — this de-biases the mean *and* gives post-t0 `g`). Per rep: within-run SEM = `SD/√Neff`. Across reps: **`SE(grand) = √(max(between_sd², within_sem²)/n)`**, with `t` on `n−1` dof when the replicate spread dominates (between-run regime) else on the pooled `ΣNeff` dof (t→1.96). Returns `{mean, ci_half, se, regime, between_sd, within_sem, …}`.
- **`hierarchical_ci_from_estimates(means, sems, neffs)`** — same variance model but from **pre-computed** per-rep scalar + within-run SEM (for χ/κ, which are fitted scalars with a *block-averaged* SEM, not raw series). Guards against all-NaN SEMs (→ SD-only CI).

**Why `max(between², within²)`**: for a *poolable* system (`within_sem ≥ between_sd`) it collapses to the pooled pseudoreplication limit (tight, `~3·Neff` samples); for a *between-run* system (AMBER/SLipids DMPG) it stays the honest replicate-spread CI — so the between-run systems are never falsely tightened. The `stats.py` `decompose()` ratio is the diagnostic that predicts which regime each cell lands in.

- **Significance testing on the same variance model** (added for the Fig. 1 brackets): `compare(ci_a, ci_b)` takes two hierarchical-CI dicts and returns a Welch-style `{delta, se, t, dof, p}` from their `se`/`dof` — so a system whose replicates disagree cannot buy significance with frame count. A raw-frame t-test would be pseudoreplication (2501 correlated frames are not 2501 samples; the real n is 3 runs) and would star nearly every pair. p-values come from a pure-numpy regularised incomplete beta (`betai`, Numerical Recipes continued fraction) + `t_pvalue(t, dof)` — **no scipy**, matching `scipy.stats.t.sf` to ~1e-10 — keeping the module's py2.7/OST compatibility. `stars(p)` maps to `***` p<0.0005, `**` p<0.005, `*` p<0.05, else `n.s.`. The regime shows in the dof: poolable DMPC APL gives dof ≈ 350–440, between-run DOPC/DMPG dof ≈ 2–4.

**Where it's consumed**: `make_equilibrium_table.py` (APL/d_HH/d_HC via `hierarchical_ci` + t0; χ/κ via `hierarchical_ci_from_estimates`), the two `*_vs_barrier` plots (through `collect()`), and `plot_tilt_modulus.py` / `plot_lipidator.py` (bar error bars). The `*_summary.json` files gained `ci95_*` fields alongside the retained `sd_*`.

## Main-text (production) figures (`figstyle.py` + `figcompose.py` + `figures/`)

The exploratory `plot_*.py` scripts write quick 300 dpi PNGs to `plots/`. The **manuscript** figures are a separate, standardised layer that writes to **`plots/final/`**, one production script per figure under **`figures/`**.

**House spec** (all of it lives in `analysis/figstyle.py`, the single source of truth — don't re-declare sizes or rcParams in a figure script): **180 mm** wide always, height flexible up to a hard **10 in** ceiling; **Helvetica** everywhere except math, which is `mathtext.fontset="stixsans"` (STIX Two Sans — italic variables and Greek that sit with Helvetica without a serif clash); **9 pt** axis labels/titles/panel letters, **7 pt** tick labels and legends; default **linewidth 1** (lines, spines, tick majors, patches); ticks **inside** the axes with labels outside, **mirrored on all four spines** but labelled only left and bottom; minor ticks on. Panel letters are **bold lower-case a, b, c**.

- **`figstyle.use()`** applies the rcParams. **`figstyle.figure(height_mm)` / `figure_grid(nrows, ncols, height_mm)`** make the canvas (constrained layout; `figure_grid` returns a *flat* axes list in reading order, which is the order the letters follow). **`figstyle.panel_labels(axes)`** letters them, and **`figstyle.save(fig, name)`** ships them.
- **`figure.dpi` is 127**, i.e. exactly 5 px/mm. At the matplotlib default of 100 the canvas' integer pixel size quantises the width to 179.83 mm.
- **Never `bbox_inches="tight"`** — the 180 mm width is load-bearing, and a tight bbox shrink-wraps it away. `savefig.bbox` is pinned to `None` in the rcParams and `save()` warns if the figure it is handed is not 180 mm.
- **`figure()` reserves a 3.5 mm band** (`LABEL_BAND_MM`, via the constrained-layout `rect`) at the top of the canvas: panel letters are figure-level text that takes no part in the layout, so without it the top row's letters are clipped by the canvas edge. Letters are placed in **figure** coordinates offset from each axes' top-left (a per-axes `transAxes` offset drifts when panels differ in height), after a `draw_without_rendering()` resolves the layout.
- **`figstyle.panel_labels(axes, inside=True)`** tucks the letters just inside each panel's top-left corner, with a soft white pad so they stay legible over data. Needed on grids with **shared** y axes: matplotlib drops the inner columns' tick labels, the panels then abut, and a default (outside) letter would land on its left-hand neighbour's frame.
- **`figstyle.categorical_x(ax)`** for a categorical x (lipid names): drops the x **minor** ticks and *all* top-axis ticks, which mark nothing between categories, keeping the labelled majors under each group. The y-axis keeps its minor and mirrored-right ticks.
- **`figstyle.mirror_ticks(ax, right_data=True)`** is the twin-axis exception the spec allows: it stops the primary axes mirroring onto the right spine and returns a labelled `twinx` that owns it (the k_BT twin of the χ / κ_θ bar charts).
- **Three files ship per figure**, from `figstyle.save()` (and identically from `figcompose`):
  - **`{name}.svg`** — *the deliverable*: standalone and monolithic, **text converted to paths** by Inkscape (`--export-text-to-path --export-plain-svg`).
  - **`{name}_text.svg`** — the same figure with editable text, for last-minute Inkscape tweaks (`editable=False` to skip).
  - **`{name}.png`** — 600 dpi, rendered *from the deliverable SVG* so the two are provably the same drawing. Exported with **`--export-width=4252`**, not `--export-dpi=600`: 180 mm at 600 dpi is 4251.97 px, so the dpi flag would leave the final pixel width to Inkscape's rounding.
- **Why the text is outlined** (this reverses the obvious default): matplotlib's `svg.fonttype="none"` keeps text editable, but mathtext then names `STIXGeneral`/`STIXNonUnicode`, which on most machines exist **only inside matplotlib's package data** — a reader without them silently gets substituted glyphs. Outlining removes every font dependency; rasterised artists are already inlined as base64, so nothing external remains.
- **Rasterise heatmaps**: pass `rasterized=True` to `imshow`/`pcolormesh` (pore-density maps, APL projections). Matplotlib inlines the raster as base64 *inside* the SVG, so the file stays monolithic while dropping from tens of MB to hundreds of kB.
- **`figures/_check.py`** verifies every shipped figure: 180 mm ± 0.05, height ≤ 10 in, no `href` pointing outside the file, no live `<text>` (fonts outlined), PNG exactly 4252 px wide with an aspect matching the SVG. Run it after any figure change — it is the regression guard against a stray tight bbox.
- **`figures/fig00_style_demo.py`** is a style proof sheet, not a manuscript figure: line + CI band, grouped bars with the k_BT twin, colour-by-ff/shape-by-lipid scatter, rasterised heatmap + colourbar, step histograms, log-log with inset — all at the real production size, so 7 pt ticks and 1 pt lines can be judged on a print-size proof.

**`analysis/figcompose.py`** covers the panels matplotlib cannot draw — the PyMOL snapshot renders, an SVG from another script, anything from a foreign tool. `Mosaic` is a 180 mm canvas written with `viewBox="0 0 180 H"`, so **one SVG user unit is one millimetre** and every coordinate in a composition script reads as a physical size. `place()` inlines a PNG as a base64 `data:` URI or splices an SVG in as a `<g transform=...>` subtree (deriving the missing side from the file's own aspect ratio); `grid_cell()` gives the regular-grid arithmetic; `text()` / `panel_letter()` add labels with an explicit **baseline** (renderers disagree about `dominant-baseline`); `save()` routes through `figstyle.finish_svg()` so a mosaic ships as the same three files. **The load-bearing detail is id namespacing**: a spliced SVG has every `id` it defines — and every `url(#…)` / `href="#…"` referring to one — rewritten with a per-panel prefix, because the `#pXXXXXXX` glyph and clip-path ids matplotlib generates otherwise collide between panels and one panel silently blanks.

**`make_figures.py`** is now a thin `Mosaic` caller: it assembles the `snapshots/*.png` renders into 1×3 per-lipid figures (`plots/final/figure_{lipid}_{last,close}.*`), 180 mm = 4 gaps of 1.875 + 3 panels of 57.5 mm, with a 5 mm band carrying the force-field heading and the panel letter. The panels are 57.5 mm / 600 dpi PNGs placed at native size, so the export is essentially 1:1 with no resampling. (It used to hand-write the SVG and *link* the PNGs by relative path with an `--embed` opt-in; embedding is now unconditional, since monolithic output is the requirement, and the output moved from `plots/` to `plots/final/`.)

**Still open**: which figures are main text and what goes in each. The `plot_*.py` scripts each build and save their own `Figure`, which cannot be pasted into a composite, so a panel destined for a main-text figure gets split into a pure **`draw_*(ax)`** function (creates no figure, saves nothing) that both the standalone script and the `figures/figNN_*.py` production script call. Do that conversion **per figure, on demand** — not as a big-bang refactor.

The style follows the `make_figures` panels (water/ions as spheres at `sphere_scale 0.5`, ions coloured explicitly since a `.gro` has no element column, opaque grey ground) with three differences: the **lipid tails stay visible**, the background is **transparent** (`ray_opaque_background 0`), and there is no cylinder marker. The zoom pads the union box by **8 Å** — at 2 Å the outermost molecules of the first frame were clipped, since `-pbc mol` leaves whole molecules poking past the box face. Two gotchas it works around: (1) **`zoom` letterboxes** against whatever viewport aspect PyMOL has in headless mode, which left both panels padded and under-scaled — so the framing is set by camera arithmetic instead (orthoscopic visible height = `2·dist·tan(fov/2)`, solved for `dist` so the view covers `box_z + 2·buffer`, with the image aspect set to the union box's aspect); (2) PyMOL gives each **loaded object a different carbon colour** (green, then cyan), so the two frames would read as different systems — `util.cbag` on both restores the green/by-element default. The **scale** is shared (one `dist`, fitted to the union *atom* extent — not the box, since `-pbc mol` leaves molecules poking out) so the taller last-frame box is a real difference on the page, but the **camera origin is per frame**: each bilayer is centred in its own box and the boxes differ in z, so a shared origin left the shorter first frame riding high (114 px of top margin against 32 px at the bottom). Both frames now sit dead-centre in their panels (162/162 and 81/81 px), with content heights 856 vs 1018 px — the real 7.5 → 9.2 nm growth. `zoom`'s leftover in-plane camera offsets were part of that bug, so `v[9:11]` are zeroed and the rotation origin set explicitly.
- The renders are tall and narrow (≈6.3 × 9.0 nm → 875 × 1181 px), so **height fills the 50 mm strip**, their width follows from the PNG aspect, and **the canvas width is set by the panels** — two renders + the 50 mm plot + two 10 mm gaps ≈ 155 mm — rather than padded out to the 180 mm page, which would only have added whitespace. This is the one deliberate exception to the 180 mm rule, so `figstyle.finish_svg` now exports the PNG at 600 dpi for the canvas' *own* width (`png_width_px`, still exactly 4252 px at 180 mm) and `figures/_check.py` carries a `NARROW_OK` set that relaxes the width check to ≤ 180 mm for those names only — the tight-bbox guard stays strict everywhere else. No panel letters — there is no room for a label band in a 50 mm strip, and none were asked for.
- The plot panel is drawn at its real 50 × 50 mm size and **spliced into the `figcompose` mosaic as an SVG** (live text; the mosaic's `save()` outlines every glyph once at the end, so the shipped SVG stays font-independent). Curve colours are **matplotlib's default cycle, deliberately not `palette`**: every curve is the same force field *and* the same lipid, so the project's force-field hues would assert something untrue. The legend is a **fully opaque white unframed box**: the curves climb through the upper-left corner, and both a transparent and a translucent legend left them crossing/ghosting through the labels.

### Figure 4 — pore-waist occupancy + snapshots (`draw_pore_occupancy.py` + `figures/fig04_pore_occupancy.py`)

**3 rows × 3 columns, 180 × 170 mm.** Rows 1–2 are the `poredens_counts_middle` content in the production style — per-frame atom count inside the **middle third** of the CV cylinder (the `_mid` keys, |z| ≤ 0.45 nm, the pore's narrowest waist) — **a/b/c** water oxygens and **d/e/f** phosphates, lipids across the columns, force fields overlaid. The standalone figure's third row (glycerol C2) is **dropped**. Row 3 (**g/h/i**) is the `figure_DMPC_last` snapshot set: the DMPC end-of-run pore in each force field, one per column, drawn as `imshow` image panels (`--lipid` switches the lipid).

- **The columns change meaning between the rows** — lipids in rows 1–2, force fields in row 3 (one lipid, three force fields; the force fields are the overlaid colours above and the columns below). Deliberate, but the caption has to say so.
- Each counts cell is a **pair of axes sharing the count axis** — a ¾-width trajectory and a ¼-width horizontal histogram — built with `outer[r, c].subgridspec(1, 2, width_ratios=[3, 1])`. Nested gridspecs are incompatible with `tight_layout` (which is why the standalone script hand-rolls its margins), but **constrained layout handles `subgridspec` fine**, so the figure keeps its exact 180 mm width for free.
- Histogram bins are **1 atom wide, centred on the integers** (the quantity is a count); each row shares one count ceiling across its three lipids so the panels are comparable; the phosphate rows use `ymin = −0.5` so the frequent 0 counts don't sit on the spine.
- The snapshot row is built with `draw_snapshot(ax, png)` → `imshow` + `set_axis_off()`, i.e. **inside the matplotlib figure** rather than through `figcompose`. A mosaic would have been the other option, but only one row is images, and keeping it in matplotlib means one layout engine, one letter sequence, and one `save()`.
- **Letter offsets are per-row-type** (two `panel_labels` calls). The counts letters use `dx_mm=-2.2, dy_mm=-1`: dropped 1 mm so they clear the **`0` tick label of the row above** (otherwise at the same height) and hug their own panel's corner, nudged 2.2 mm left so they sit just outside the plotting area. The snapshot letters keep the default height (nothing above them to clear) with **dx=0** — image panels have no tick margin, so any negative offset pushes the leftmost letter off-canvas. The house default of −5.5 mm assumes a y-tick-label margin and lands on the *previous* cell's histogram here.
